# 明细表底稿生成

## 概述

将科目余额表数据批量填充到底稿模板中。支持多公司、往来科目账龄计算、披露分类、关联方识别。

## 可用工具（按调用顺序）

| 工具 | 用途 | 何时调用 |
|------|------|---------|
| `detailed_table_inspect` | 检查数据源结构 | 第一步，了解数据有什么列 |
| `detailed_table_inspect_template` | 检查模板结构 | 第二步，了解模板有什么 Sheet 和批注字段 |
| `detailed_table_save_config` | 保存配置决策 | 每步配置确认后调用 |
| `detailed_table_validate` | 校验配置完整性 | 所有配置填完后调用 |
| `detailed_table_generate` | 执行生成 | 校验通过后调用 |

## 完整工作流程

```
1. inspect + inspect_template（并行）→ 了解数据结构和模板结构
2. AI 一次性分析所有配置 → 展示给用户确认
3. save_config × N（并行保存所有配置）
4. generate → 生成（内部自动校验）
```

**速度优化要点：**
- inspect 和 inspect_template 应并行调用
- 所有配置一次性展示给用户确认，不要逐步确认
- 确认后所有 save_config 并行调用
- 省略 validate 步骤，generate 内部会校验并在失败时报错

**关键原则：所有配置一次性展示给用户确认，确认后批量保存。用户可以要求调整。**

## 配置规则详解

### 一、路径配置（paths）

告诉程序数据在哪里、结果放哪里。

```
paths 配置:
- output_dir: 输出文件夹路径（必需）
- sources: 数据源映射（必需）
  - 键名: 自定义数据源名称（如"科目余额表"、"辅助科目余额表"）
  - 值: 文件路径或文件夹路径
  - 文件夹路径用于多期数据（如往来账龄需要多期文件）
  - 多期文件需在文件名前加序号（由近及远），如: "1.2023.xlsx", "2.2022.xlsx"
- copy_empty_template: 无数据时是否复制空底稿（默认 false）
```

**AI 判断要点：**
- 用户通常只给一个数据文件，默认命名为"科目余额表"
- 如果用户提到"往来"、"账龄"、"辅助"，可能需要多个数据源
- 检查数据源中是否有"客户名称"、"供应商名称"等往来相关列

### 二、字段名称映射（field_mapping）

将**标准字段名**（模板批注）映射到数据源的**实际列名**。

#### 2.1 固定标准字段（必须映射）

| 标准字段 | 含义 | 常见实际列名参考 |
|---------|------|----------------|
| 公司名称 | 公司/单位名称 | 公司、单位名称、企业名称 |
| 科目名称 | 一级会计科目名 | 会计科目、科目、一级科目 |

#### 2.1.1 "公司名称"字段的两种模式

**AI 必须在配置前询问用户选择哪种模式：**

**模式 A：每个公司分别生成一套底稿**
- 数据源中需有公司标识列（如"公司主体刷"）
- field_mapping 中将"公司名称"映射到该列
- 程序会按公司名称分组，每个公司生成独立的底稿文件

**模式 B：所有公司合并到一套底稿**
- 所有数据写入同一个底稿模板
- 需要为"公司名称"提供一个所有行都相同的值
- 两种实现方式：
  1. 数据源中已有一列所有值相同（如"公司分组刷"中所有公司同属一个集团）→ 映射到该列
  2. 数据源中没有统一列 → 映射到一个实际存在的列，但用户需知道这会导致所有数据合并在一个底稿中
- 如果模板 Sheet 有"公司主体"批注，数据会按公司分行展示；"公司名称"控制的是底稿文件的拆分维度

**AI 判断要点：**
- 先看 inspect 返回的数据，是否有公司标识列
- 主动询问用户：是要每个公司分开底稿，还是所有公司合并在一个底稿
- 根据用户选择配置"公司名称"的映射
| 期初余额 | 期初/年初余额 | 期初数、年初余额、年初借方余额 |
| 本期借方 | 本期/本年借方发生额 | 本期借方发生额、本年借方金额、借方金额 |
| 本期贷方 | 本期/本年贷方发生额 | 本期贷方发生额、本年贷方金额、贷方金额 |
| 期末余额 | 期末/年末余额 | 期末数、期末借方金额、年末余额 |

**AI 判断要点：**
- 仔细看 inspect 返回的实际列名和数据预览
- "期初余额"和"本期借方"容易混淆："期初"是时点数，"本期"是期间发生额
- 如果同时存在"年初借方余额"和"本年借方金额"，前者是余额，后者是发生额
- "本期借方"应映射到**发生额**列，不是**余额**列

#### 2.2 可选标准字段（根据需要映射）

| 标准字段 | 含义 | 何时需要 |
|---------|------|---------|
| 客户编号 | 往来单位编号 | 往来科目（应收/应付等） |
| 客户名称 | 往来单位名称 | 往来科目 |
| 二级科目名称 | 二级/明细科目名 | 需要明细分类时 |
| 披露 | 披露分类项目 | 模板中有"披露"批注时 |
| 关联方 | 关联方标识 | 需要识别关联方时 |
| 账龄:N | 第 N 期账龄金额 | 往来科目多期数据时（N 从1开始） |

#### 2.3 模板批注特殊语法

模板批注（单元格批注文字）本身也支持特殊语法：

**批注语法 1: `:` 多期字段**
- 批注如 `本期借方:1` 表示第 1 期的借方金额
- 用于多期数据/账龄场景
- `:` 前的部分必须是 field_mapping 中的标准字段名
- 示例：批注 `期初余额:2` → 映射到 field_mapping 中"期初余额"对应的数据列，带期号后缀

**批注语法 2: `#` 聚合分组**
- 批注如 `客户名称#` 表示按此列的值聚合（相同值合并为一行，金额求和）
- 用于往来科目中同一客商有多笔明细需要合并的场景
- `#` 在批注文字末尾

#### 2.4 field_mapping 值的特殊语法

**规则 1: `/` 借贷拆分**
- 用法: `借方列名/贷方列名`
- 含义: 借方科目用 `/` 左边的列，贷方科目用 `/` 右边的列
- 示例: 数据源有"客户-贸易伙伴"和"供应商-贸易伙伴"两列
  → 填写 `客户-贸易伙伴/供应商-贸易伙伴`
  → 应收账款（借方科目）用"客户-贸易伙伴"，应付账款（贷方科目）用"供应商-贸易伙伴"

**规则 2: `-` 优先顺序**
- 用法: `首选列名-备选列名-备选列名`
- 含义: 优先用第一个，为空则用第二个，以此类推
- 示例: 数据源有"客户名称"和"贸易伙伴名称"
  → 填写 `客户名称-贸易伙伴名称`
  → 优先用客户名称，为空则用贸易伙伴名称

**规则 3: `$` 关联表查找**
- 用法: `$列名`
- 含义: 用该列的值去查关联映射表，得到最终值
- 前提: 必须同时配置对应的映射表（如 `$会计科目描述` 需要配置 disclosure）
- 示例: `$会计科目描述`
  → 程序读取该行"会计科目描述"列的值（如"其他应收款-保险理赔"）
  → 去"披露"映射表中查找 → 得到"赔款和罚款"
  → 填入模板的"披露"位置

**规则 4: `/` 和 `-` 可以组合使用**
- 示例: `客户名称-贸易伙伴名称/供应商名称-贸易伙伴名称`
- 解读: 借方科目优先用"客户名称"→"贸易伙伴名称"，贷方科目优先用"供应商名称"→"贸易伙伴名称"

**规则 5: field_mapping 的键名 = 模板批注名**
- field_mapping 中 mapping 的每个键，必须与模板 Sheet 中的批注文字**完全一致**
- 系统会扫描模板每个 Sheet 的所有单元格批注，将批注文字与 field_mapping 的键逐一匹配
- 匹配成功后，用 mapping 的值（数据源列名）从数据中取值，填入对应列
- **不需要映射的批注**：以下批注是系统特殊标记，不要放入 field_mapping：
  - `尾行` — 数据区域结束标记
  - `项目名称` — 系统自动填入报表科目名称（report_subject）
- 示例：模板批注有"客户名称"，mapping 就必须有 `"客户名称": "数据源列名"`

**规则 6: text_fields（文本字段）**
- 某些字段虽然值是数字（如客户编号），但需要作为文本处理，防止 Excel 自动转换
- 在 field_mapping 中添加到 text_fields 数组里

**规则 7: 科目名自动去空格**
- 系统会自动去除数据源中科目名称的首尾空格
- 因此 subject_mapping 中只需写去空格后的科目名即可
- 示例：数据源中 "其他应收款 " 和 "其他应收款" 都会被匹配到 subject_mapping 中的 "其他应收款"

**规则 8: uniqueness_fields（唯一性字段）**
- 往来科目多期数据需要确定唯一性，用于关联不同期的同一笔往来
- 通常是: 公司名称 + 客户名称（+ 二级科目名称）
- 在 field_mapping 中添加到 uniqueness_fields 数组里

**AI 判断要点：**
- 先看 inspect 返回的列名和数据预览
- 判断哪些列对应哪个标准字段
- 看模板批注里是否有额外字段（如"披露"、"关联方"、"账龄:N"）
- 如果模板中有"披露"批注，检查是否需要 `$` 语法（查看模板中是否需要从二级科目分类）
- 如果模板中有"账龄:N"，检查数据源是否是多期（文件夹 vs 单文件）

### 三、科目与报表科目对应（subject_mapping）

将数据源中的**一级科目**映射到**报表科目**，并指定借贷方向和正负号。

#### 3.1 字段说明

```
每个科目一行:
- subject: 一级科目名称（从数据源提取，去重）
- report_subject: 报表科目名称（会计判断）
- symbol: 借贷方向（"借" 或 "贷"）
- sign: 正负号（"正" 或 "负"）
- source: 数据来源（MCP 流程中固定填写 `"default"`）
- generate: 是否生成底稿（true/false）
```

#### 3.2 借贷方向（symbol）判断规则

| 科目类型 | 方向 | 示例科目 |
|---------|------|---------|
| 资产类 | 借 | 库存现金、银行存款、应收账款、固定资产、无形资产 |
| 资产备抵类 | 贷 | 坏账准备、累计折旧、累计摊销、存货跌价准备 |
| 负债类 | 贷 | 短期借款、应付账款、应付职工薪酬、应交税费、长期借款 |
| 所有者权益类 | 贷 | 实收资本、资本公积、盈余公积、利润分配 |
| 收入类 | 贷 | 主营业务收入、其他业务收入、营业外收入、其他收益 |
| 成本费用类 | 借 | 主营业务成本、管理费用、销售费用、财务费用、税金及附加 |
| 特殊 | 贷 | 本年利润 |

#### 3.3 正负号（sign）判断规则

- **正**: 期初期末余额不变号（直接使用原值）
- **负**: 期初期末余额变号（取相反数）

**关键：sign 不是按科目类型硬查表，而是要看数据的实际符号来判断。**

判断步骤：
1. 从 inspect 返回的数据预览中，查看该科目类型下各公司的期初余额和期末余额的实际数值
2. 如果大多数数值为正数 → sign = "正"（数据本身就是按会计习惯的，不需要变号）
3. 如果大多数数值为负数 → sign = "负"（需要取反，使其在底稿中以正确符号呈现）

实际经验:
- 大部分数据源中，负债类科目余额本身就是**正数**（按会计习惯），此时 sign = "正"
- 少数数据源中，负债类科目余额带负号（如 -1000），此时 sign = "负"（取反变正）
- 资产备抵类科目（累计折旧、坏账准备）：余额为正 → sign="正"，余额为负 → sign="负"
- 少量异常值（如某公司某科目为负数但其他公司为正数）是正常的，以大多数为准
- 如果数据源中有"借贷方向"/"余额方向"列，可以作为辅助判断依据

AI 判断示例:
```
数据预览显示:
  应付账款 期初余额: 500000, 300000, 1200000 → 都是正数 → sign = "正"
  应付账款 期初余额: -500000, -300000, -1200000 → 都是负数 → sign = "负"
  累计折旧 期初余额: 80000, 45000, 200000 → 都是正数 → sign = "正"
```

#### 3.5 是否生成（generate）判断

- 只有需要生成底稿的科目才设为 true
- 通常只对有模板的报表科目设为 true
- 如果用户只要求生成某个科目，只将该科目设为 true
- 如果用户要求生成全部，则所有有模板的科目都设为 true

#### 3.6 数据来源（source）

- **MCP 流程中固定填写 `"default"`**
- 程序内部将 file_path 参数作为默认数据源，key 为 "default"
- paths 配置中的数据源名称仅用于 GUI 旧流程

**AI 判断要点：**
- 从 inspect 返回的 subjects 列表提取所有一级科目
- 参考上表做映射，但要根据实际数据调整
- 特别注意: 同名科目出现在不同公司可能需要统一映射
- 系统自动去除科目名首尾空格，mapping 中写无空格版本即可
- generate 字段只对用户要求生成的科目设 true

### 四、科目与底稿模板（template_assignment）

将**报表科目**匹配到**模板文件**和**Sheet名**。

```
配置格式（注意键名是 "assignment"，不是 "mapping"）:
{
  "assignment": [
    {
      "report_subject": "报表科目名称",
      "template_path": "模板文件的绝对路径",
      "sheet_name": "模板中的 Sheet 名称"
    }
  ]
}
```

**AI 判断要点：**
- 先调用 inspect_template 看模板有哪些文件和 Sheet
- 根据报表科目名和模板文件名/Sheet名做匹配
- 常见匹配规律:
  - 文件名通常包含科目名或编号（如 "B09-其他应收款.xlsx"）
  - Sheet名通常包含"明细表"字样
  - 如果一个模板文件有多个Sheet，选择最合适的（通常是"xxx明细表"或"xxx-披露表"）
- 如果用户只要求生成特定科目，只匹配该科目
- 如果找不到精确匹配，选择最接近的并提示用户

### 五、自定义映射配置（通用机制）

除了 4 个固定配置外，可以创建**任意数量的映射配置**。映射配置用于 `$` 前缀的间接查找场景。

**原理：**
- `config_type` = 模板中的批注名（如"披露"、"关联方"）
- `save_config` 保存后，`generate` 自动发现并加载
- field_mapping 中用 `$列名` 标记哪些字段需要通过映射表转换

**配置格式：**
```json
{
  "mapping": {"原始值1": "目标值1", "原始值2": "目标值2"}
}
```

**常见映射示例：**

| config_type | 触发条件 | mapping 示例 |
|---|---|---|
| 披露 | field_mapping 有 `"披露": "$二级科目"` | `{"保险理赔": "赔款和罚款", "保证金": "保证金及押金"}` |
| 关联方 | field_mapping 有 `"关联方": "$客户名称"` | `{"公司A": "子公司", "公司B": "合营公司"}` |
| 自定义 | field_mapping 有任意 `$` 前缀字段 | 任意 key-value |

**AI 判断要点：**
- 先看模板批注中有哪些需要映射的字段
- 再看数据源中哪列的值需要被映射（field_mapping 中 `$` 后面的列名）
- 从数据中提取该列的去重值列表
- 根据值的含义建立映射关系
- 需要用户提供信息时（如关联方清单），主动询问

## 注意事项

1. **配置顺序有依赖**: paths → field_mapping → subject_mapping → template_assignment → 映射配置（可选）
2. **各配置类型的 JSON 结构**:
   - `paths`: 扁平对象 `{"output_dir": "...", "sources": {...}}`
   - `field_mapping`: `{"mapping": {...}, "text_fields": [...]}`
   - `subject_mapping`: `{"mapping": [{...}, ...]}`
   - `template_assignment`: `{"assignment": [{...}, ...]}`（注意键名是 `assignment`，不是 `mapping`）
   - 自定义映射配置: `{"mapping": {...}}`
3. **work_dir 贯穿全程**: 所有配置保存在同一个 work_dir 下，generate 时读取
3. **多期数据**: 往来账龄需要文件夹路径（而非单文件），文件名前加序号
4. **科目名自动去空格**: 数据源中科目名可能有尾随空格（如"银行存款 "），系统会自动去除，mapping 中写无空格版本即可
5. **模板批注是关键**: 模板中哪些字段需要填充，完全由批注决定。一定要先 inspect_template 看清楚
6. **只依赖 Skill 规则**: 不要去读源码了解实现细节，所有操作规则都在本文档中。打包后源码不可读
7. **映射配置是动态的**: 除了 4 个固定配置外，可以创建任意数量的映射配置，config_type 就是模板批注名
