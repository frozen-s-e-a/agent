# 自建 Agent 方案

面向所内部署的本地模型，在**短期内无法更换更强模型**的前提下，通过自建 agent 运行时和客户端，尽量抵消模型能力不足（思考深度低、多重任务易漏、有效上下文有限）带来的影响，让 agent 能**准确、稳定**地完成任务量较大的审计任务。

## 核心原则

- **流程由代码控制**：高频审计任务固化为工作流，模型只在指定节点做指定的小事；规划、执行、验证分离。
- **代码算数，模型写判断**：大数据量由程序处理，模型只看汇总表和异常清单。
- **按有效上下文做预算**：标称 128k，按实测有效长度（初始 32k）规划。
- **结果可验证、可追溯、可恢复**：每步由代码强制校验，每个数字可追溯到源数据，任务可从检查点续跑。
- **先诊断再改造**：配置问题和模型能力问题症状相同，先区分再对症处理。

## 实施路线（详见 08 第八节）

| 阶段 | 内容 |
|---|---|
| 0 | 诊断与基准：修复配置类问题，建立评估集和基准指标 |
| 1 | 基础设施：模型网关、上下文管理器、事件流客户端、调用日志 |
| 2 | 编排器与工作流引擎：状态机、检查点、验证器、自由模式循环 |
| 3 | 数据层与首批程序：标准数据、导入适配、日记账测试、银行流水、往来款项 |
| 4 | 交互与底稿：程序映射、参数确认、下钻、底稿输出、可追溯验证 |
| 5 | 知识资产与扩展：审计手册抽取、更多程序与行业配置 |
