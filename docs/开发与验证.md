# 开发与验证

源代码遵循原方案中的 client / host / contracts / conversations / task-scheduler / audit-worker / file-ops 等职责边界。当前只有实际用到的模块包含实现，未用空目录冒充能力。

## 开发

1. Node.js 24.19.0、pnpm 11.19.0，执行 `pnpm install --frozen-lockfile`。
2. 准备 Python 3.12，执行 `python -m pip install --target build/python-packages -r requirements.txt`。
3. 执行 `node scripts/runtime.mjs <Python 安装目录>`，复制独立运行时到 build。
4. 执行 `pnpm dev`。开发状态位于 artifacts/dev-state，不使用日常项目与会话。

## 验证命令

```text
pnpm typecheck
pnpm build
pnpm test
node --test tests/integration/scheduler.test.mjs
build/python/python.exe -B tests/integration/test_worker.py
build/python/python.exe -B scripts/benchmark.py 100000
```

桌面端到端：执行 `node tests/e2e/desktop.mjs` 检查实际 Electron 窗口和 Python 工具。可额外传入打包 exe 路径，检查自带运行时。入口仅加载本地文件，后台使用管道通信，没有浏览器运行模式。

## 构建测试包

`pnpm package:test` 生成 artifacts/test/windows-x64/0.1.0-internal.3/AI助手。相同版本目录存在时拒绝覆盖，需要显式更新版本后重新打包。

这不是正式发布脚本。完整首版发布必须继续满足原文档中 P0–P4 的全部退出标准。
