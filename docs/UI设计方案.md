# AI 审计工作空间 UI 设计方案

> 本文是 UI 实现前的设计基线。先确认信息架构、页面职责和交互路径，再进入组件拆分与视觉实现。

## 1. 产品定位

产品定位为面向审计人员的本地优先审计工作台。

核心任务链：

**选择资料 → 选择核查方式 → 执行任务 → 查看结果 → 保留证据**

页面始终回答四个问题：

- 我现在在哪个项目里？
- 当前处理哪些资料？
- 下一步应该做什么？
- 结果保存在哪里，是否可追溯？

## 2. 信息架构

- **项目**：每个项目包含授权文件、对话、任务记录和 `outputs` 结果目录，是审计工作的边界。
- **对话**：自然语言入口，支持模型、处理模式、附件和工具调用，是所有任务的主工作区。
- **工具**：表头识别、凭证核查、月度分析、规则检查等可复用能力，按“输入 → 参数 → 输出”配置。
- **设置**：模型服务、资源权限、用量统计、扩展能力和迁移诊断，与日常核查路径分离。

## 3. 总体布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部栏：当前项目 / 当前对话 / 本地运行状态 / 面板开关          │
├──────────────┬───────────────────────────────┬───────────────┤
│ 左侧导航      │ 主工作区                       │ 项目资料面板   │
│ 新建对话      │ 欢迎页 / 对话流 / 任务结果       │ 当前项目       │
│ 工具搜索      │                               │ 文件浏览器     │
│ 项目列表      │                               │ 已选文件       │
│ 独立对话      │                               │ 输出说明       │
│ 设置          │                               │ 运行状态       │
│ 本地状态      │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

| 区域 | 主要职责 |
| --- | --- |
| 左侧导航 | 切换项目、对话、工具和设置 |
| 顶部栏 | 告知当前位置、当前会话和系统状态 |
| 主工作区 | 完成对话、工具配置和结果查看 |
| 右侧资料面板 | 管理文件范围和项目上下文 |
| 底部输入区 | 输入自然语言、上传附件、选择模型和处理模式 |

## 4. 新用户首屏

首屏只回答三个问题：资料放在哪里、如何开始核查、结果在哪里查看。

```text
本地审计工作台

让每一步审计，都有据可循。

从一份资料开始，把整理、核查与分析交给工具。

┌──────────────┬──────────────┬──────────────┐
│ 1            │ 2            │ 3            │
│ 划定资料范围  │ 选择核查方式  │ 查看可追溯结果 │
│ 选择项目文件夹│ 选择工具或描述 │ 结果自动归档   │
└──────────────┴──────────────┴──────────────┘

可用工具数量    本地处理       结果可追溯

常用工具：
[查看数据结构] [凭证借贷核查]
[月度分析]     [JET 规则检查]

查看全部工具    使用合成示例
```

### 首屏交互

1. 点击“划定资料范围”打开创建项目。
2. 点击“选择核查方式”打开工具搜索。
3. 点击常用工具直接进入工具参数页。
4. 点击输入框可以直接用自然语言开始。
5. 没有项目时，涉及文件的操作统一提示先创建项目。

首屏指标使用真实运行数据：可用工具数量来自启动信息；“本地处理”和“结果可追溯”是稳定的产品承诺，不使用静态数字暗示未实现能力。

## 5. 页面设计

### 5.1 项目工作区

项目是所有资料和结果的边界，包含：项目名称、项目文件夹、项目内对话、已授权文件、`outputs` 输出目录和任务执行记录。

项目创建流程：

```text
输入项目名称 → 选择文件夹 → 确认数据范围 → 进入项目工作区
```

### 5.2 对话页面

支持自然语言描述任务、`/工具名` 快速调用工具、添加文件/文件夹/图片、切换文本和视觉模型、选择本地处理模式、查看工具调用过程、查看任务结果和 Token 用量。

输入框提示：

> 描述你的审计任务，或输入 `/` 选择工具……

### 5.3 工具搜索页

工具搜索页负责发现和选择能力。每个工具显示名称、解决的问题、所需输入、输出结果类型、所属分类和兼容验收状态。

推荐分类：数据结构、凭证核查、月度分析、规则检查、文件处理、原版 MCP 工具。

工具卡片示例：

```text
凭证借贷核查
检查凭证中借方和贷方金额是否平衡

输入：序时账或凭证文件
输出：差异清单、核查结果、来源索引

[开始配置]
```

### 5.4 工具参数页面

采用三段式配置，避免一次出现大量高级参数：

```text
01 选择输入文件
02 确认字段与参数
03 处理方式与输出
```

第一步提供文件夹浏览器、文件复选框、已选文件标签、文件预览、表头和工作表识别。

第二步将必填字段放在前面，自动识别字段名，支持候选值，高级参数默认折叠，并提供参数示例。

第三步展示轻量本地、自动选择、大批量处理、输出格式和原文件保护说明。

底部固定操作：

```text
原文件保持不变                         [确认并执行]
```

### 5.5 任务结果页面

任务执行展示完整结果卡，而不是只显示“已完成”：

```text
凭证借贷核查
已完成

处理文件：3 个
发现问题：12 条
输出文件：2 个
执行耗时：18 秒

[打开结果文件] [查看校验清单] [查看执行详情]
```

统一状态：排队中、执行中、正在停止、已完成、已取消、执行失败、待恢复。

失败状态必须说明原因和处理方式，例如：

> 未找到“凭证日期”字段。请确认表头名称，或在高级参数中填写字段映射。

### 5.6 右侧项目资料面板

右侧面板包含当前项目名称、项目路径、输入文件、已选文件数量、文件夹导航、清除选择、使用工具、原文件保护说明和本地计算引擎状态。

空状态文案：

> 为资料划定工作范围  
> 选择一个文件夹作为项目，每个项目的文件和对话独立保存。

### 5.7 设置页面

设置页面与日常核查流程分离，分类为模型服务、资源与权限、用量统计、扩展能力、迁移与诊断。

模型服务页面重点展示服务地址、API 密钥、获取模型、文本模型、视觉模型、测试连接、温度和最大输出 Tokens。

## 6. 视觉设计规范

### 6.1 色彩

| 用途 | 颜色 |
| --- | --- |
| 主背景 | `#F5F7FA` |
| 左侧导航背景 | `#F7F5F1` |
| 左侧导航文字 | `#6D675F` |
| 导航强调色 | `#D97757` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#172235` |
| 辅助文字 | `#7B879A` |
| 主强调色 | `#25B58A` |
| 深色强调 | `#16856A` |
| 边框 | `#E5EAF1` |
| 成功状态 | `#EAF8F3` |
| 警告状态 | `#FFF6E6` |
| 错误状态 | `#FFF1ED` |

视觉关键词：安静、清晰、专业、本地可信、结果可追溯。避免使用大面积渐变、过多装饰和密集的彩色卡片。

### 6.2 字体和间距

- 中文：Microsoft YaHei UI
- 英文和数字：Inter / Segoe UI
- 正文：13px；辅助信息：10–11px；页面标题：26–39px；重要数值：18–30px
- 基础间距使用 8px 的倍数

### 6.3 圆角和层级

- 导航项：7px
- 输入框：7–9px
- 普通卡片：10–12px
- 大型弹窗：14px
- 使用细边框和低强度阴影表达容器层级
- 状态同时使用颜色和图标表达

### 6.4 动效

只保留按钮悬浮、流式输出光标、任务进度、成功和错误提示等必要反馈，并遵守 `prefers-reduced-motion`。

## 8. 响应式方案

### 桌面端

- 左侧导航固定
- 中央对话区自适应
- 右侧项目资料面板固定
- 工具卡片两列显示

### 窄屏

- 右侧资料面板隐藏，可通过顶部按钮打开
- 工具卡片改为单列
- 三步引导改为纵向排列
- 设置页签改为横向滚动
- 输入区保留附件、工具和发送按钮

## 9. 当前项目功能映射

| 现有功能 | UI 入口 |
| --- | --- |
| 创建项目 | 首屏第一步、左侧项目区域、右侧空状态 |
| 项目文件浏览 | 右侧项目资料面板 |
| 文件授权 | 文件复选框和已选文件区 |

| 任务执行 | 对话流中的任务卡 |
| 输出文件 | 任务结果卡 |
| 迁移状态 | 左侧迁移入口、设置中的迁移与诊断 |

## 10. 方案验收标准

- 新用户进入后能在 5 秒内理解第一步操作。
- 创建项目后能清楚看到当前资料范围。
- 工具名称和用途不依赖内部命令名。
- 常用工具不超过两次点击即可进入。
- 高级参数默认隐藏。
- 执行中、成功、失败和取消状态明显可区分。
- 结果文件和校验清单可以直接访问。
- 页面在窄屏下仍可完成核心流程。
- 原文件保护和本地处理状态始终可见。

## 11. 实现顺序

1. 完成 AppShell、左侧导航、顶部栏和右侧资料面板。
2. 完成首屏三步引导和常用工具入口。
3. 实现工具搜索和三段式参数配置。
4. 补充任务结果卡、输出文件和失败恢复。
5. 实现设置页面、响应式细节和无障碍检查。

实现过程中保持现有 API、任务调度、附件和模型服务逻辑不变，UI 只负责信息组织、状态呈现和操作入口。
