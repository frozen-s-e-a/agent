## ADR-010：共用 SQL 规则的两种本地执行路径

当前轻量模式使用 Python + DuckDB 内存连接，批量使用 Python + DuckDB 落盘连接。两者流式导入、共用规则 SQL，避免重新实现两套定点金额和全局窗口口径。轻量不强制创建持久分析库，仍保存结果 Parquet 和来源证据。

与原 pandas 轻量方案有明确差异：启动仍依赖 DuckDB，尚未比较启动成本。独立 Python 进程每 250 毫秒监控 RSS；查询预算为任务预算一半。不是 OS 级硬沙箱，也没有声明能杜绝瞬时超额。

目前只做步骤重试；没有分片恢复、缓存复用、磁盘使用实时监控或网络盘原子发布保障。输出原子目录重命名面向本地文件系统。以上都是正式首版的未完成工程项。

## 工程实现

- Electron renderer 沙箱、contextIsolation、禁用 nodeIntegration；限定桥接动作，不暴露任意 shell。
- Electron 主进程启动独立 Node Host；Host 仅绑定 127.0.0.1，API 需要随机 bearer token，页面有 CSP。
- SQLite 保存项目、任务、设置；会话 JSONL 追加并 fsync，截断的尾事件不当作已提交记录。
- API 密钥由 Electron safeStorage 在 Windows 加密，不进入 SQLite、事件或诊断。
- Python 工具只读取项目范围内真实路径；拒绝路径穿越和指向授权范围外的链接。
- 作业排队、取消、失败、重试、程序重启中断标记；取消与发布竞争时以已校验结果为准。
- 运行目录和合成测试结果均与源代码分开。打包不携带旧程序 exe、pyd、原生研究包或真实底稿。

## ADR-013：有界本地工具调用循环（internal.5）

模型请求携带工具定义；流式工具参数组装完成后才分派。保留 reasoning_content 与 tool_call_id 关联，将真实结果交回模型继续请求。执行入口为项目／已发送附件、只读预览、登记审计工具和本对话任务；路径经过 realpath 检查。附件工作副本使用 hash 验证并生成内部项目，结果沿用任务调度和校验发布。工具错误作为结果返回，网络／中断／轮数限制明确结束。最多 8 轮、16 次工具调用，停止信号传递到模型、预览和当前任务。该流程替代此前“仅参数卡片执行”的状态，不扩展原审计规则的兼容性声明。
