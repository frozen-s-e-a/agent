# Agent 工作流实施记录

日期：2026 年 10 月 12 日。

本轮按《审计Agent平台项目方案》和《审计Agent工作流与准确性设计》把用户入口改为自然语言对话，并把现有独立审计程序接入 Agent 执行链路。用户不再从任务卡选择节点或填写内部参数；用户描述目标、范围和成果要求，Agent 依据项目资料与已登记的工作流选择本地能力。

## 已落地

- `src/client/AgentChatWorkspace.tsx`：聊天式任务入口。支持项目切换、新建对话、自然语言输入、附件、停止、历史对话、实时阶段状态、步骤事件和成果回查；原任务工作台不再是默认入口。
- `src/agent/definitions.mjs`：把 63 项独立审计工具和 16 项通用操作绑定到 9 个内置业务工作流。每条流程固定协调、理解、执行、校验和交付节点；模型不能生成未登记的工作流或工具。
- `src/agent/inputs.mjs`：保存选定项目资料的哈希和隔离快照，执行前后可识别资料变化。
- `src/agent/context.mjs`：为每次模型请求保存最终消息、工具定义、要求引用、资料哈希、预算和请求摘要。预算使用 UTF-8 字节上界，未把未测量的 tokenizer 数值标成确定能力。
- `src/agent/validation.mjs`：对实际任务状态、成果文件存在性、格式和 SHA-256 做发布前检查；文件完整性通过不代表业务语义自动通过。
- `src/host/service.mjs`：创建 `agentRuns`，保存目标、流程版本、节点、请求、调用、状态、未决项、用量和完成/失败检查点；聊天回合结束后标记完成、待补充、停止或失败。
- `src/host/model-tools.mjs`：独立审计任务返回后进入统一成果检查，失败不能伪装成完成。
- `src/harness-adapter/agent.mjs`：支持请求前记录、响应后用量登记、节点轮次和可配置的轮数/工具调用预算。

## 用户操作

1. 建立或选择项目。
2. 在“任务对话”中直接描述目标，例如“检查这些资料是否齐全，并列出缺失字段”。
3. Agent 先读取资料范围和结构，再自动调用匹配的独立审计程序；必要时在对话中提出业务问题。
4. 对话中显示实际步骤、当前状态、警告和阶段成果。停止后已经完成的成果仍然保留。
5. 后续消息继续使用同一对话上下文；历史对话可以恢复查看。项目原文件不覆盖，输出进入任务成果目录。

## 当前边界

- 本轮完成了工作流执行骨架、持久化记录和聊天入口。业务语义标准、每个任务的逐字段通过条件、OCR 真实返回合同和外部服务恢复仍按 Agent 方案中的 G01–G10 继续细化和实测。
- 模型请求预算使用保守字节上界。企业网关的真实 tokenizer、工具调用兼容性和 128K 截断信号仍需真实接口验证。
- 已有独立审计任务保持本地 Python 运行，不依赖原 SW 审计工具箱。

- Vite 生产构建通过，聊天入口被纳入构建。
