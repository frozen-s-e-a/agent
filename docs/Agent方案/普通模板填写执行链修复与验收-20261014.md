# 普通模板填写执行链修复与验收

版本：0.1.0-internal.36。基础提交：c52a81c，包含之前的重复读取修复；本次修改未提交或推送。

原设计要求真实执行、稳定保存映射、遇到歧义提问、按实际成果验收。前一版本接入旧审计程序，却没有无批注工作簿的直接填写路径；真实运行停留在读取，未形成计划或补充问题。本次补齐该路径。

## 实现

- 填写任务提供工作簿清单及按坐标分页读取；区分原值、公式缓存和表头候选，不把首行或样本自动当作已确认表头。初次结构返回控制在工具预算内。
- 保存普通模板的来源、表头、期间依据、全量行范围、筛选规则、目标区域和必填位置。程序执行求和、唯一匹配、复制、算术及受控文字提取；可按目标行的实际键批量汇总填写，无需模型逐行输出大计划；不接受任意代码或模型猜测的业务数值。
- 保存计划后直接进入执行路径。填写前三张表时检查实际工作表清单，禁止漏表、换表或用结构检查/列提取替代填写。任务指南按原目标加载，继续时保留有效计划及输入版本。
- 缺失金额、歧义年份、重复匹配、表头与数据混淆、未决必填项和不可核对的目标公式进入具体补充问题。未解决的问题阻止填写或完成，普通“继续”不能代替口径回答。
- 只修改原模板包中的指定单元格与受影响公式缓存。其他包部件、工作表、样式、公式文本、合并区域等核对保留；输入原件不覆盖。支持的模板公式执行确定性计算；不能计算的目标公式保留未完成状态。
- 写入前核对计划与来源哈希；写入后重新打开实际工作簿，逐项比较全部必填位置，并核对未授权变动。成果附写入计划和填写核对记录，验证级别为 mapped_write_and_reread。
- 修正计划哈希的跨进程稳定性与模型请求失败后的历史附件恢复。已经验证的映射在重启后可继续执行；资料变化使旧计划失效。

## 验证范围

102 项 Node 单元与集成回归通过；12 项工作簿执行器案例通过；3 项填写链路集成案例通过。另通过 TypeScript 检查和生产构建。

填写案例使用本机脚本模型与真实 Python 执行器：无批注附件的 120 行明细全部参与计算，三张目标表的 12 个必填/公式位置重读通过；年份冲突在写入前转成问题；重启后恢复计划而不重新读取。覆盖空白金额、重复键、漏填、重复写入、合并区域、错误表头、输入变化和未计算公式等失败情况。

用户原附件仅在隔离副本上读取。哈希与原附件一致，确认 BKD24 第 2 行为表头，结构返回不再因体积过大只留下归档索引。原资料包含多种目标年份，Sheet1 的“本期借方”等表头无法单独证明年份；新校验对此生成具体问题，并在写入前等待，不擅自选择期间或金额方向。

本次没有调用真实企业模型，没有修改生产数据库，也没有宣称该原附件已经按业务正确口径填完。模型自主选择映射的效果仍需真实企业模型验证；通用业务语义验收集、OCR、新增 MCP 等其他未完成范围仍按原实施记录区分。桌面程序包和单文件启动检查结果记录在 artifacts/workbook-execution-20261014。
