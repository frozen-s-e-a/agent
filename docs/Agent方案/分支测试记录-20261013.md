## 128K 运行时补齐

随后补齐了设计稿中原先只有原则、但运行时还没有完整落实的四项机制：

1. 当前 Agent 回合达到预算前，按用户回合和工具交互单元归档；最近交互、用户要求、任务计划、未决问题、成果状态和证据索引继续保留。归档只移出模型历史，完整结果仍保存在不可变记录中，可按引用和范围重新读取。
2. 状态上下文增加输入别名、来源引用、结果引用、样本标记和输出截断恢复信息，压缩前后可以核对要求、输入版本和证据身份。
3. 外层 Agent 和 Python 审计工具内部模型遇到 `finish_reason=length` 时，保存已经返回的片段并继续请求；工具参数不完整时仍不会执行，JSON 结果必须在完整解析后才发布。
4. 未选择具体工作流时只向模型加载审计工具的精简合同；选择工作流后再加载对应工具的完整参数定义。工具名称仍由程序授权校验，减少 128K 上下文中无关工具合同的占用。

新增压力测试覆盖当前回合 20 次大结果回查、输出续写和 Python JSON 续写；Node 测试总数为 67，Python transport 单元 2 项通过，通用资料、工作簿和附件测试 32 项通过。历史 108K 估算运行本地重放时从 38 条消息压缩到 12 条，保留 20 条结构化证据索引。

另外修复了等待补充问题时的附件续传：问题卡提交和“继续任务”现在都会把草稿附件 ID 传给 `agent.resume`，后端在恢复运行时重新建立附件输入快照。新增回归测试确认附件会进入恢复任务的 `run.inputs`，不再只读取原项目资料。

## 上下文重建器 v4 与无准备窗口启动

后续复测定位到零保留分支的 `slice(-0)` 仍保留全部工具循环，以及恢复时上一轮消息、完整要求和状态重复进入上下文的问题。v4 在每个层级约束模型视图，完整状态、原文、工具合同和历史交互以会话隔离的压缩记录保存，引用按原始路径分页读取，不修改原要求或工具调用参数。最近的有界证据页保留原文，供给覆盖仅在成功请求实际携带原文后确认；省略的必要要求未读完整时不会放行执行或最终完成。模型网关的上下文错误自动进入更小的重建请求。

Python 内部模型采用同一 token 估算口径，大输入在任务目录保存原文及进度，按页读取并提交分段 JSON 数组；模型传输仅允许已配置的对话接口，外部审计查询继续受限。企业模型实际服务尚未在线验收。

验证包含 75 / 75 Node 测试、7 / 7 Python 模型传输、27 / 27 通用处理、5 / 5 工作簿和附件测试、覆盖 63 个程序的 83 / 83 合成案例，另有归档专项 11 项及归档后的任务集成 2 项。恢复约 18 万字要求的任务，在模拟网关拒绝和过早完成声明后，读完原文并实际完成本地处理。4 次历史预算失败输入只读重建后，估算输入降至 33,251–46,197 token；状态哈希完整保留，未访问用户模型服务或修改用户任务。

启动器不创建准备窗体。首次或更新仍需释放压缩内置文件，已有运行目录直接复用，损坏目录修复后保存活动目录指针。单实例锁会唤回仍未关闭的旧版窗口，因此同版本更新必须退出旧进程后再启动。最终源码、测试日志和程序包验证记录见随包验收记录。

## 发送附件的实际执行链修复

16:17 的恢复运行确实预览了聊天发送的 `投资收益2025空模板.xlsx`，附件哈希与发送记录一致。该运行使用上下文重建器 v4，未因上下文预算中断；停止前有 97 次工具调用、90 次模型请求，但没有创建真实审计任务。主要失败来自两个分离的执行入口：通用 `run_audit_tool` 只接入通用处理器，对目录中的独立程序错误返回“尚未实现”；直接 `audit_*` 把附件编号或尚未创建的工作路径当作项目文件。预览中使用 `sheet_name` 的调用还被忽略，读取了默认工作表。

附件现在在每次运行开始时复制到该运行的隔离工作目录并校验哈希，预览、通用处理和独立审计共享同一份输入身份。附件编号、输入编号和工作路径统一解析；存在同名资料时要求明确引用，不自动选错文件。计划及实际调用先转换为同一工作路径再匹配。`run_audit_tool` 支持目录中的独立程序，工具合同查询同时接受能力编号和模型函数名，并返回两者的对应关系。预览支持 `sheet_name` / `header_row` 别名，冲突或不支持的参数会明确报错；明细表检查合同增加实际表头行参数。结果显示原始文件名、附件引用和样本范围，避免将有限预览当成完整读取。
