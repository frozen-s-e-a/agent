# 重复读取修复与验证

日期：2026-10-14。基础提交：`c52a81cba64e95f0e35e2ac36bd5d095a7e5faf4`，分支：`claude/project-thread-u73bmt`。本次补丁未提交或推送，桌面测试版本继续为 `0.1.0-internal.35`。具体源码哈希随程序包保存。

## 实际故障

用户反馈的运行先成功回查了 5 次证据，随后模型在两次达到输出上限的回复中反复叙述同一操作，约 60 次。该回合没有执行填写任务，却以“已完成”结束。之前的四项真实任务均为工作簿结构检查，不是填表成果。

历史结果列表混入了大量读取和上下文归档记录，模型已有任务编号仍寻找结果引用。原循环保护只覆盖失败工具调用，没有覆盖成功但无新增数据的读取，也没有检测单次回复内的重复正文。进度查询结束后，“那继续做”还丢失了原来的填写目标。

## 修复

1. `read_agent_result` 接受 `taskId`，直接读取当前对话任务的完整原始返回，按实际 `nextOffset` 分页；旧保存引用仍可用，会话归属校验继续有效。
2. 结果列表按真实任务去重，任务状态、工具参数及直接读取提示由实际任务提供，读取记录不再成为新的任务结果。
3. 成功读取相同证据范围且没有新增数据时提示模型使用已有证据；连续重复达到阈值时停止空转。新页、新数据及实际审计执行可以继续，没有统一轮数上限。
4. 流式回复出现长段重复时停止生成，保存诊断并将任务标为未完成，避免达到输出上限后再次续写重复正文。正常输出续写保留。
5. 普通“继续”继承之前的处理要求；进度查询仍可只读结束。明确处理要求不能只靠读取或说明就标为完成，填写要求还需实际生成可核对的表格成果。
6. 已保存的重复回复在下一次模型上下文中替换为故障提示；用户原话、正常历史和磁盘完整事件记录保留。

## 验证

- Node 单元及集成测试：99 / 99 通过，包含成功重复读取、重复正文、原目标续接、进度查询及 282 条历史包装记录下的真实成果生成。
- TypeScript 检查、Vite 生产构建通过。原有超过 60 次正常调用、大结果分页、输出续写、停止、补充问题及附件执行回归通过。
- 生产记录只读回放：四项真实任务经 58 次分页读取，与原始返回逐段一致；任务结果索引为 4 项。两段实际重复正文均被识别，续接目标恢复为原填写要求。
- 程序目录和单文件启动验证结果分别保存在 `artifacts/repeat-read-20261014/package-check.json` 与 `launcher-check.json`；成功后才替换桌面 EXE，并保留旧文件备份。
