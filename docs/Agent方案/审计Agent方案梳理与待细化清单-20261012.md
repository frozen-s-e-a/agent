## 当前最影响准确性的缺口

首要缺口是关键业务判断的通过条件。方案要求做“语义校验”，但程序究竟根据什么接受一个字段映射、认定一个匹配唯一、批准一个账龄结果，还需要按任务明确。

以期末余额映射为例，需要固定以下内容：

|检查|需要具体回答的问题|
|---|---|
|含义|如何区别期初余额、借方发生额、贷方发生额和期末余额，依据是表头说明、资料定义还是已验证规则？|
|范围|字段属于哪家公司、哪个期间和币种，是否存在合并与单体口径差异？|
|转换|万元或元、括号负数、借贷方向怎样转换，无效值怎样记录？|
|控制关系|当前资料确实具有哪些可用的余额关系或关联账表，检查适用条件和容差是什么？|
|矛盾与未决|字段名支持一个解释但数据或附注支持另一解释时，先查什么，何时保持待核实？|
|标准案例|选对和选错的案例分别是什么，哪些错误即使总额一致也必须被发现？|

将上述内容落实为规则、来源和检查器，才能在模型提出错误候选后定位并拒绝放行。同一错误映射同时进入生成和重读计划时，文件可能与计划一致，因此需要独立业务依据和标准答案。

|5|恢复、版本变更、局部修复、发布及准确性验收规范|标准集能覆盖中断、错填、漏填、范围变更、关联错误和误报完成|
|6|新平台页面、逐状态交互及事件合同|从下任务到成果回查和继续执行有完整可审阅流程，界面与真实状态对应|

单工具格式和参数可以直接引用已有资料。新增文档应集中补齐任务级语义、跨工具衔接和验收规则，避免反复重写产品定位或重复抄录工具清单。

## 文档一致性需要整理的地方

|事项|建议整理方式|
|---|---|
|产品实施阶段与技术细化步骤粒度不同|合并为一份带依赖和验收产物的实施清单；以明细底稿先验证机制，与银行、月间等优先流程共同纳入最终全部范围|
|协调、处理、检查职责与需求、字段、分析、复核角色命名不同|建立职责到节点的对应表，区分角色配置和模型实例，不由角色数量决定模型调用次数|
|任务、阶段、节点、业务单元和问题之间关系|在共用合同中统一定义：任务可组合流程，流程含节点，节点按需执行一个或多个业务单元问题，并保留相应结果|
|执行、数据校验、语义核实和发布状态|统一枚举与呈现规则，明确状态转换；在界面中展示真实验证程度|
|当前版本的视觉和手动参数说明与新平台设计不同|基线说明保留版本；新增平台合同明确 OCR 和自动参数来源，通过支持矩阵列出差异|
|预算、修复次数、接口假设和验收目标|在配置及验证记录中标记待测或已确认，写明生效版本，避免变成未经测量的固定保证|

本次梳理的完成结果是明确设计成熟程度、待细化合同和验证依赖。后续推进以具体合同、标准案例及实际验证结果判断完成。
