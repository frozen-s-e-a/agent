## 结论

- **现在的程序**是一个桌面对话应用，由三部分组成：
  - Node 写的 Agent 长对话循环：模型自己挑工具，外面加了很多护栏；
  - 一次性启动的 Python 工作进程：跑 63 项审计工具和填表执行器；
  - React 对话界面。
- **基础部分可以留下：**
  - 桌面外壳和打包；
  - 项目、会话、附件快照、凭据加密；
  - 内置 Python 环境，所需的 DuckDB、openpyxl、pandas 都已在里面；
  - 填表执行器和表格导入的核心逻辑。
- **Agent 核心要整体换掉：**
  - Node 运行时、工作流合同、技能注入，换成新的 Python Agent 服务；
  - 方案里最关键的几块现在都没有，要新写：
    - 底稿结构识别；
    - 口径与受控计算；
    - 守恒、控制数、双路复算这套核对；
    - 模型网关；
    - 评估。
- **规模估计：**
  - 现有约 1.2 万行代码（不含测试）中，约 3,100 行的 Agent 相关代码和技能文档会被替换；
  - 约 1,200 行的 Python 填表和导入代码改造后继续使用；
  - 其余基本保留或小改；
  - 新写部分以 Python 为主，按设计第十八节分阶段做。

### 1.2 一个任务现在怎么跑

1. 用户发消息，运行时把未完成运行的要求合并进来。
2. 用正则判断要不要进入填表模式。
3. 模型拿到系统提示、技能指南和最多约 80 项工具，进入循环：
   - 模型选工具、给参数；
   - Node 校验后交给 Python 执行；
   - 结果放回对话，继续下一轮。
4. 对话涨到约 9.2 万估算 token 才压缩。
5. 最终答复是模型原文。

所有调用用同一组参数：temperature 0.2、max_tokens 4096，没有约束解码。

### 2.5 我先按这几项默认做

1. **Node 后端首版保留。**
   - 现有项目、会话、附件、设置、凭据的代码稳定、有测试，首版继续由 Node 后端负责。
