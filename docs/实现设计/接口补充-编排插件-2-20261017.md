# 接口约定补充（二）：前端接入后补的几处（Harness 接入线程，2026-10-17）

这些是前端接入 PR #4 后提出的缺口，已在 PR #3 实现，提交 927ee8c。请接口约定线程合入，前端线程按此对接。

1. **新事件 `task.resumed {from, stage}`**：暂停或阻塞的任务继续时立即发出。`from` 取 paused 或 blocked，`stage` 是当前阶段。
2. **应用正常退出**：宿主发 `shutdown` 时，进行中的任务先存为 paused，再发 `task.blocked`，内容为 `{where, why:'应用退出，任务中断', suggest:'继续任务', paused:true}`。这条在输出关闭前发出，宿主可以去掉自己补的那条。进程被强行结束时不会发，宿主重启后用 `task/list` 看到 paused。
3. **`task/get` 的 regions 增加字段**：`range`、`type`、`purpose`、`headerRows`、`totals`（合计行行号）、`manual`（人工填写的格）。字段与 `overlay.regions` 一致，原有的 `state`、`attempt`、`refs`、`card`、`reason` 不变。
4. **`confirmTools` 支持排除项**：以 `!` 开头的项是排除项，例如 `['mcp__oa__*', '!mcp__oa__query_*']`。
5. **新增启动参数 `disabledTools`**（环境变量 `AUDIT_DISABLED_TOOLS`）：写法与 confirmTools 相同，用来传设置里停用的工具。这些工具对模型隐藏，调用会被拦下。名单在启动时读入，设置改动后需要重启 Harness，与外部 MCP 服务配置改动时一样。没有改 src/audit-mcp/server.py。
6. **追问和关闭通知**：`question.request` 现在都带 `callId`，不限时的追问也带。`approval.closed` 和 `question.closed` 带 `sessionId`，撤回时带 `withdrawn: true`。
