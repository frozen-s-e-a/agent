## 一、分层与通信

```mermaid
flowchart LR
    FE["新前端"]
    HOST["应用宿主（Node）<br/>设置 · 凭据 · 项目 · 文件 · 转发"]
    DSH["DeepSeek Harness（固定版本）<br/>+ 编排插件 + 桥接插件"]
    TOOLS["审计工具服务（Python，MCP）<br/>底稿 · 资料 · 查询 · 核对 · 填写"]
    LLM[("企业模型<br/>OpenAI 兼容格式")]

    FE <-->|"前端命令 + 流程事件（第三节）"| HOST
    HOST <-->|"SDK 协议（JSON-RPC，经桥接插件）"| DSH
    DSH <-->|"MCP 工具调用（第二节）"| TOOLS
    DSH --> LLM
```

| 接口 | 双方 | 方式 | 版本标识 |
|---|---|---|---|
| 工具接口 | 编排插件、Harness → 审计工具服务 | MCP（标准输入输出） | `audit-tools/1` |
| 流程事件 | 编排插件 → 宿主 → 前端 | 事件流 | `audit-events/1` |
| 前端命令 | 前端 → 宿主 | 请求-响应 | `audit-app/1` |
| 界面卡片 | 编排插件 ⇄ 前端（经宿主） | 卡片随事件下发，回答随命令上传 | `audit-cards/1` |

**规则：**
- 前端只和宿主通信，不直接接触 Harness 的内部事件。Harness 升级时，只有宿主和插件需要改。
- 审计工具服务不依赖 Harness。它是普通的 MCP 服务器，可以单独测试。
- 模型看不到全量数据。工具返回的数据都按 2.5 控制体量。

### 1.1 宿主与 Harness 的连接（已定）

依据 [Harness 接入实测](Harness接入实测-20261017.md)第六、七节，在假模型下测试通过。

**连接方式：SDK 协议加我们的桥接插件，不用 ACP。**
- 桥接插件在 Harness 进程里，替换 dsh `sdk` profile 自带的 `sdk-jsonrpc-server`。宿主在标准输入输出上按行收发 JSON-RPC。
- dsh 原有的方法照旧（`initialize`、`session/prompt`、`session/wait`、`session/resume`、`shutdown`，通知 `session.event`、`session.status`）。
- 新增请求：`session/cancel`、`approval/respond`、`question/respond`、`card/answer`、`bridge/status`。
- 新增通知：`assistant.stream`、`approval.request` / `approval.closed`、`question.request` / `question.closed`、`card.opened` / `card.closed`。
- `question.request` 都带 `callId`，不限时的追问也带。`approval.closed` 和 `question.closed` 带 `sessionId`，撤回时带 `withdrawn: true`。
- **取消**在进程内完成：`session/cancel` 停止这一轮，结束原因为 `aborted`，会话可以继续发消息。`session/resume` 只用于 Harness 进程崩溃后的恢复。

**卡片回答：宿主发 `card/answer` 请求，直达等待中的编排插件。**
- 原暂定的"带标记的用户消息 + `agent/pre-step` 拦截"实测不可行：编排插件在工具调用里等卡片时，消息一直排在收件箱里，工具不返回就不会进入下一步，`agent/pre-step` 也不触发。
- 编排插件调用 `ctx.auditCards.open(agent, card, signal)` 出卡并等待回答；桥接插件发 `card.opened`，宿主把前端的 `card.answer` 转成 `card/answer`。
- 一轮被取消时，等待中的卡片自动撤回，推送 `card.closed`，带 `withdrawn: true`。
- 未答的卡片不落盘。Harness 进程退出后它们随之消失；编排插件从检查点续跑时重新出卡（新的 `C-` 编号），宿主对旧卡推送 `card.closed`（`withdrawn: true`）。

**一个 Harness 进程只服务一个项目。**
- dsh 调用 MCP 工具时不带会话信息，审计工具服务无法按会话区分项目，所以访问范围按进程定。
- 宿主打开项目时启动一个 Harness 进程，切换项目时换进程（启动到就绪约 2 秒）。前端不受影响，只是切换项目时短暂等待。

### 1.2 宿主与编排插件之间的请求

编排插件在 PR #3 实现（依据：[接口补充-编排插件](接口补充-编排插件-20261017.md)、[接口补充-编排插件-2](接口补充-编排插件-2-20261017.md)）。底稿任务的请求也经桥接插件走 JSON-RPC：

| 请求 | 参数 → 返回 | 对应前端命令 |
|---|---|---|
| `task/create` | `{ sessionId, text, files, message? }` → `{ task }` | `task.create`；对话中由 Agent 登记时宿主也调它 |
| `task/get` | `{ task }` → 4.4 的快照 | `task.get` |
| `task/list` | `{}` → `[ { task, session, status, text, deliverables, createdAt, finishedAt } ]` | `task.list` |
| `task/message` | `{ task, text }` | `task.message` |
| `task/cancel` | `{ task }` → `{ cancelled }`。暂停或阻塞中的任务也能取消，未答卡片撤回 | `task.cancel` |
| `task/resume` | `{ task }` → `{ resumed }` | `task.resume` |
| `task/rerun` | `{ task, scope: { regions?, fromStage? }, note? }` → `{ queued }`，`fromStage` 默认 `basis` | `task.rerun` |
| `ids/allocate` | `{ prefix: "C" \| "O" }` → `{ id }` | 无（宿主内部） |
| `audit/tool` | `{ name, arguments }` → 2.4 的信封。只开放 `trace_cell`、`fill_preview`、`table_view` | `cell.trace`、`sheet.view`（叠加写入计划）、`table.view` |

- 流程事件由编排插件以通知 `task.event { sessionId, task, type, data, ts }` 发出。`seq` 和 4.1 的外层信封由宿主加。
- `task.created` 里的 `project` 由宿主补；对话中登记的任务，`message` 也由宿主补（`task/create` 传了 `message` 时插件原样带上）。
- **应用退出：**宿主发 `shutdown` 时，进行中的任务先存为 `paused`，再发 `task.blocked`，内容为 `{ where, why: "应用退出，任务中断", suggest: "继续任务", paused: true }`，在输出关闭前发出，宿主不用自己补。进程被强行结束时不会发这条；宿主重启后用 `task/list` 能看到这些任务是 `paused`，用 `task/resume` 继续。

## 二、通用约定

### 2.1 编号

| 对象 | 格式 | 例子 |
|---|---|---|
| 项目 | `P-` + 短编号 | `P-7f3a` |
| 对话 | `S-` + 短编号 | `S-41d2` |
| 对话消息 | `M-` + 序号 | `M-0007` |
| 任务 | `T-` + 短编号 | `T-0c21` |
| 产出文件 | `O-` + 序号 | `O-0003` |
| 输入文件快照 | `F-` + 哈希前 12 位 | `F-9a1be04c77d2` |
| 底稿结构图 | `W-` + 序号 | `W-003` |
| 区域 | 结构图编号 + `#` + 序号 | `W-003#R5` |
| 资料表 | `D-` + 序号 | `D-002` |
| 结果表 | `R-` + 序号 | `R-012` |
| 结果中的行 | 结果编号 + `#` + 行号 | `R-012#17` |
| 卡片 | `C-` + 序号 | `C-004` |
| 模板指纹、方案 | `TPL-` / `PLAN-` + 哈希前 12 位 | `TPL-51c0e2a9b3f1` |

- 编号在项目内唯一，由生成方分配，其他方只引用不改写。
- `C-`、`O-` 有两个生成方，共用编排插件的项目计数：任务的卡片和产出由编排插件分配；宿主自己的对话产出和动作确认卡从 `ids/allocate`（1.2）取号。
- 审计工具服务生成的编号（`W-`、`D-`、`R-`、`FP-`、`TPL-`）连同其内容持久保存在项目的数据目录里，服务重启后仍然有效。Harness 进程被结束后续跑时，编排插件会继续引用之前的编号。
  - 位置：`AUDIT_STATE_DIR/tools/`（`AUDIT_STATE_DIR` 由宿主按项目给出，和编排插件的检查点同一个目录）。里面有编号计数、各对象的 JSON、输入文件快照和项目分析库 `analysis.duckdb`（资料表 `D002`、结果表 `R012` 等）。
  - 模板库默认也在这里（`templates/`）；设置 `AUDIT_TEMPLATE_DIR` 后改放到该目录，可以跨项目共用。
- 单元格写作 `工作表!A1`，区域写作 `工作表!A1:D20`。工作表名含空格或符号时加单引号，例如 `'2025 明细'!B3`。

### 2.2 数值

- 金额、数量一律用**十进制字符串**传递，例如 `"-1234.50"`，不用浮点数。
- 空白、零、无效值三者分开：空白为 `null`，零为 `"0"`，无效值见 2.4 的数据问题。
- 日期用 `YYYY-MM-DD`，期间用 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD/YYYY-MM-DD`。

### 2.3 依据

凡是会影响结果的判断，都带一个 `basis` 字段：

| 取值 | 含义 |
|---|---|
| `user` | 用户原话或回答 |
| `confirmed` | 本任务已确认的口径 |
| `template` | 底稿上的标示（表头年份、"单位：万元"等） |
| `profile` | 项目档案 |
| `data` | 从资料中确定 |
| `inferred` | 推断。影响结果时必须进入确认 |

需要时另带 `basisRef`，指向具体来源（单元格、消息编号、档案字段）。

### 2.4 结果信封

每个工具调用都返回同一结构：

```json
{
  "ok": true,
  "data": {},
  "warnings": [],
  "refs": ["R-012"],
  "truncated": false,
  "next": null
}
```

失败时：

```json
{
  "ok": false,
  "error": {
    "code": "HEADER_MISMATCH",
    "message": "底稿!C4 实际文字为“期末余额”，与引用的“期初余额”不同",
    "where": "底稿!C4",
    "hint": "核对区域语义中引用的坐标和原文",
    "retryable": true
  }
}
```

**错误分类：**

| 类别 | `code` 前缀 | 处理方 |
|---|---|---|
| 参数或引用错误 | `ARG_`、`REF_`、`HEADER_` | 回给模型修正（`retryable: true`） |
| 核对不通过 | `CHECK_` | 编排插件按失败矩阵重做 |
| 数据问题 | `DATA_` | 暂停，出卡片给用户 |
| 需要用户输入 | `NEEDS_INPUT` | 出卡片 |
| 文件或环境问题 | `IO_`、`ENV_` | 报告阻塞 |

### 2.5 体量控制

- 单次返回给模型的内容不超过约 2,000 token。超出时 `truncated: true`，`next` 给出取下一页的参数。
- 大结果只返回编号、行数、合计和前 N 行。全量留在项目分析库。
- 原始数据明细不返回给模型。模型看到的是结构、统计和少量样例。

### 2.6 文件

- 工具只能访问当前项目目录和任务工作目录。
- 资料和底稿挂在项目上，项目里的所有对话共用。对话中附上的文件也先登记为项目资料，消息只引用它的 `F-` 编号。
- 用户原文件只读。所有输出写到新文件：底稿任务的写到 `输出/<任务编号>/`（任务编号由 `fill_compile`、`fill_apply` 的 `task` 参数给出），对话产出写到 `输出/<对话编号>/`。
- 输入文件在任务开始时生成快照（`F-` 编号）。快照哈希变了，依赖它的结果全部失效。
- 审计工具的 `file` 参数可以是 `F-` 编号，也可以是项目目录内的相对路径。第一次用到时复制快照，之后都按快照计算，用户在 Excel 里继续改原文件不影响已经开始的任务。目前支持 `.xlsx`、`.xlsm`、`.csv`；`.xls` 返回 `IO_UNSUPPORTED`，提示先另存为 `.xlsx`。
- 同一任务重复写出时文件名加序号（`…-填写成果-2.xlsx`），不覆盖已有产出。

## 三、工具接口（`audit-tools/1`）

审计工具服务是一个 MCP 服务器，在 Harness 里挂载为 `audit`。下列每个工具对应一个 MCP 工具，名称即下表的名称，模型看到的是 `mcp__audit__<工具名>`。参数和返回值都放在 2.4 的信封里。

本节的新工具在 `src/audit-mcp/audit_tools/` 实现，在服务进程内执行；旧工具仍各起一个子进程。依赖 `duckdb`、`openpyxl`，缺少时服务只提供旧工具。

**过渡期：**现有的旧工具（63 项）已挂在同一服务里，有两处和本文不一致：
- 金额是浮点数，不是 2.2 的十进制字符串；
- 产出写在 `outputs/<任务编号>/`，不是 2.6 的 `输出/<任务编号>/`。

旧工具先不改。本节的新工具按本文约定写；新工具覆盖了某项旧工具的功能后，旧工具从模型可见的清单中移除。

**参数：**


`sheets` 为空表示全部可见工作表。

**返回 `data`：**

```json
  "workpaper": "W-003",
  "fingerprint": "TPL-51c0e2a9b3f1",
  "sheets": [
    {
      "name": "应收账款",
      "hidden": false,
      "protected": false,
      "usedRange": "A1:K60",
      "meta": [
        { "label": "被审计单位", "labelCell": "应收账款!A2", "valueCell": "应收账款!B2", "kind": "entity" },
        { "label": "单位：元", "cell": "应收账款!J2", "kind": "unit", "unit": "元", "scope": "sheet" }
      ],
      "regions": [
        {
          "id": "W-003#R5",
          "range": "应收账款!A5:H30",
          "type": "fixed_table",
          "typeCertain": true,
          "headerRows": [5, 6],
          "columns": [
            { "col": "C", "path": ["期末余额", "账面余额"], "labelCells": ["应收账款!C5", "应收账款!C6"] }
          ],
          "rowLabels": [
```

**区域类型 `type`：**`detail_table`（明细表）、`fixed_table`（固定项目表）、`form`（表单字段）、`checklist`（检查表）、`text`（文字区）、`none`（不需填写）。`typeCertain: false` 时，`ambiguities` 写明歧义。

### 3.3 `workpaper_region_view`

**参数：**`{ "region": "W-003#R5", "rows": [7, 40] }`，`rows` 可选，用于大区域分批。

**返回：**区域的紧凑文字渲染，只含坐标、标签原文和待填标记，不含数值明细。供区域语义节点直接放进上下文。

### 3.4 `workpaper_semantics_check`

**参数：**模型给出的区域语义（结构见第五节 5.2 的底稿理解卡，同一份数据）。

**校验：**
- 引用的坐标存在，原文一致；
- 期间、单位与标签一致；
- 每个待填位置都有归属。

**返回：**`{ "errors": [ { "code": "REF_TEXT_MISMATCH", "where": "应收账款!C5", "message": "引用的表头是“期末余额”，单元格实际是“期初余额”" } ] }`。`errors` 为空表示通过；`code` 以 `HEADER_` 或 `REF_` 开头。参数格式错误时返回 `ARG_` 错误信封。

### 3.5 `data_inspect` 与 `data_import`

**`data_inspect` 参数：**`{ "file": "F-…" }`

**返回：**`{ "tables": [ … ] }`，每张识别出的表一项：

```json
{
  "candidate": "F-…/序时账/1",
  "sheet": "序时账",
  "headerRows": [1],
  "dataRange": "A2:N48210",
  "rows": 48209,
  "columns": [
    { "col": "A", "header": "日期", "types": { "date": 48209 }, "nulls": 0, "samples": ["2025-01-02"] }
  ],
  "totalsRows": [48211],
  "kindGuess": null
}
```

**`data_import` 参数：**

```json
{
  "candidate": "F-…/序时账/1",
  "kind": "journal",
  "fields": [
    { "col": "A", "name": "凭证日期", "meaning": "voucher_date", "type": "date", "basis": "data" },
    { "col": "H", "name": "借方金额", "meaning": "debit", "type": "decimal", "basis": "data" }
  ],
  "excludeInvalid": false
}
```

`excludeInvalid`：默认 `false`。用户在追问卡（5.6）里选择"排除无效值所在的行"后，编排插件带 `true` 重新导入；被排除的行号记在资料表上，`data_quality` 和 `table_view` 都能看到。

`kind`：`trial_balance`、`journal`、`bank_statement`、`ledger_detail`、`aging`、`contract`、`other`。核对工具按字段的 `meaning` 找列（如余额表的 `account_code`、`closing`），所以余额表至少要标出这两个含义。标准视图暂不建立。

`type`：`decimal`、`date`、`text`、`integer`。数值和日期按严格规则解析：千分位、全角数字、括号负数、`¥` 和 `%` 能解析，`-` 记为 0；`12万` 这类文字是无效值，不会当作 0。日期接受 Excel 日期、`2025-03-01`、`2025/3/1`、`2025年3月1日`、`20250301`。

**返回：**`{ "table": "D-002", "version": 1, "rows": 48209, "invalid": [ { "col": "H", "count": 3, "samples": [ { "row": 102, "value": "12万" } ] } ], "excluded": 0, "totalsRows": [48211] }`。

- 无效值阈值：任一列超过 10 个或超过数据行的 0.1%，返回 `DATA_INVALID_VALUES`，`detail.invalid` 与上面的 `invalid` 同形。未超过时照常导入，无效值记为空并列在 `invalid` 里。
- `excludeInvalid: true` 时含无效值的行不导入，`excluded` 是排除的行数。
- 合计行（`totalsRows`）不导入。同一候选表再次导入时沿用原来的 `D-` 编号，`version` 加 1；之前的结果在 `lineage.inputs` 里记着 `D-002@v1`，可以据此判断是否过期。
- 资料表里每行带来源文件、工作表和原始行号（`table_view` 的 `source`）。

### 3.6 `query_validate` 与 `query_run`

**参数：**

```json
{
  "sql": "SELECT ... FROM D002 ...",
  "inputs": ["D-002", "R-011"],
  "purpose": "W-003#R5 账龄分段",
  "maxRows": 5000
}
```

- 只允许 `SELECT`、`WITH`，一次一条；只能引用 `inputs` 中声明的表，SQL 里写作去掉短横线的名字（`D-002` → `D002`）；函数白名单见附录。表函数（如 `read_csv`）和文件路径都不允许，分析库本身也关闭了文件和网络访问。
- `query_validate` 只解析、不执行，返回 `{ valid, inputs, columns }`。
- 执行限时 120 秒，`maxRows` 默认 5,000，最大 50,000；超出返回 `ARG_TOO_MANY_ROWS`。结果列名不能重复，也不能以下划线开头。
- 错误都是可重试的 `ARG_` / `REF_`：`ARG_NOT_SELECT`、`ARG_MULTIPLE_STATEMENTS`、`ARG_SQL_SYNTAX`、`ARG_FUNCTION_NOT_ALLOWED`、`REF_NO_INPUTS`、`REF_UNDECLARED_TABLE`、`REF_UNKNOWN_COLUMN`、`ARG_QUERY_TIMEOUT`、`ARG_DUPLICATE_COLUMNS`。

**`query_run` 返回：**

```json
{
  "result": "R-012",
  "rows": 6,
  "columns": [ { "name": "账龄段", "type": "text" }, { "name": "金额", "type": "decimal" } ],
  "sums": { "金额": "1834500.00" },
  "head": [ ["1年以内", "1200000.00"] ],
  "lineage": { "inputs": ["D-002@v1"], "sql": "…" }
}
```

### 3.7 核对类工具

**`check_basis`：**输入 `{ region, basis }`，`basis` 为 7.1 的口径要素对象，检查是否齐全、`basis` 是否成立。返回 `{ "passed": false, "missing": ["期间", "账龄起算日"] }`。

**`check_conservation`：**输入 `{ "from": "D-002", "result": "R-012", "amount": "金额", "excluded": "R-013" }`。返回 `{ passed, items, message? }`，`items` 每项 `{ check, passed, detail }`：`amount_nulls`（金额为空）、`unassigned_rows`（分组列全空的行）、`duplicate_groups`（分组重复，关联放大的迹象）。

- 可选 `sourceAmount`、`sourceFilter`：来源表上的 SQL 表达式（如 `"借方金额" - "贷方金额"`、`"科目编码" = '1122'`）。给出时再核对 `amount_conserved`：来源合计 = 结果合计 + 排除合计。
- `excludedAmount`：`excluded` 结果表里的金额列名，默认与 `amount` 相同。

**`check_control`：**

```json
{
  "region": "W-003#R5",
  "left":  { "result": "R-012", "column": "金额", "op": "sum" },
  "right": { "kind": "balance", "table": "D-001", "account": "1122", "field": "closing" },
  "tolerance": "0"
}
```

返回 `{ "passed": false, "left": "…", "right": "…", "diff": "…", "explainedBy": [] }`。

- `right`（`left` 同样可用）的 `kind`：
  - `balance`：余额表 `table` 里科目编码为 `account` 的行，`field` 取 `closing`、`opening`、`debit`、`credit`（按字段的 `meaning` 找列）；
  - `result`：另一张结果表某列的合计，`{ kind: "result", result, column, op: "sum" }`；
  - `value`：给定的数，`{ kind: "value", value: "1835000.00" }`，只用于用户在卡片上确认过的数；
  - `query`：一条受控查询，返回一行一列，`{ kind: "query", sql, inputs }`。
- 给了 `excluded`（结果编号）且差额正好等于它的合计时算通过，`explainedBy` 列出该编号。
**`check_compare`：**输入 `{ left, right, mapping }`（两个结果编号和列的对应关系）。返回 `{ passed, differences }`，`differences` 列出不一致的项，以及两路查询在来源、期间、范围、方向上的差别。

- `mapping.columns` 是要比较的金额列（左边的列名），省略时比较左边全部金额列；`mapping.right` 可以写出左列对应的右列名，两边各只有一个金额列时自动对上。
- 两边按非金额列（如账龄段、客户）对齐后逐行比较，行的顺序不影响结果；`differences` 每项 `{ key, column, left, right, diff }`，两路查询口径上的差别每项 `{ aspect, left, right }`。

所有核对的结果都记在项目里，`trace_cell` 按结果编号和区域取最新一次显示。

### 3.8 `fill_compile` 与 `fill_apply`

**`fill_compile` 参数：**

```json
{
  "task": "T-0c21",
  "workpaper": "W-003",
  "bindings": [
    {
      "region": "W-003#R5",
      "cells": [
        { "cell": "应收账款!C7", "from": { "result": "R-012", "row": 1, "column": "金额" }, "scale": "1" }
      ],
      "manual": ["应收账款!H7"]
    }
  ],
  "overwrite": []
}
```

- `from` 也可以是 `{ "profile": "entityName" }`（项目资料：审计工具状态目录下的 `profile.json`，键值对，目前由宿主写入）或 `{ "text": "C-004", "content": "…" }`（第八节说明文字：卡片编号加确认后的文本）。
- 不允许直接给数值。
- `scale` 是除数：结果是元、底稿是万元时写 `"10000"`。`rounding` 可选，保留的小数位数；`scale` 不是 1 又没给 `rounding` 时保留两位。
- `cell` 可以省略工作表名，按区域所在的表。写入位置必须在区域内；公式格（`REF_FORMULA_CELL`）、合并单元格内部（`REF_MERGED_CELL`）、同一格绑两次（`ARG_DUPLICATE_CELL`）、结果行或列不存在（`REF_ROW_OUT_OF_RANGE`、`REF_UNKNOWN_COLUMN`）都按区域列出，错误信封的 `detail.errors` 是全部错误 `[ { code, message, region, where } ]`。
- 来源值为空的格列为人工填写。区域里没绑定、也没列为人工的待填格，自动列为人工填写，并在 `warnings` 里说明。
- 已有内容的格不在 `overwrite` 里时，列进 `overwrites`（`{ cell, old, value }`），这一版计划不能写入；用户确认后带上这些格重新编译。
- 明细表行数不够时，返回需要扩展的行数，由编排决定是否扩展。

**返回：**`{ "plan": "FP-…", "cells": 96, "manual": 4, "manualCells": […], "overwrites": [], "expand": [], "output": "输出/T-0c21/应收账款底稿-填写成果.xlsx", "regions": [ { "region", "cells", "sources" } ] }`，或按区域列出错误。`output` 是将要写出的文件路径，写入确认卡（5.5）显示它。`task` 决定输出目录（2.6）。`expand` 每项 `{ region, rows, after }`：在第 `after` 行后需要再加 `rows` 行。

**`fill_apply` 参数：**`{ "task": "T-0c21", "plan": "FP-…", "approvedCard": "C-006", "excelRecalc": true }`。没有已批准的写入确认卡，返回 `NEEDS_INPUT`。`task` 要和编译计划时的一致，否则 `ARG_TASK_MISMATCH`。计划里还有未确认的 `overwrites` 或需要扩展的 `expand` 时也返回 `NEEDS_INPUT`（暂不支持自动插入行）。

**返回：**

```json
{
  "output": "输出/T-0c21/应收账款底稿-填写成果.xlsx",
  "checks": {
    "readback": "passed",
    "formulas": "passed",
    "crossFoot": "passed",
    "untouched": "passed",
    "completeness": "passed",
    "excel": "passed"
  },
  "manualCells": ["应收账款!H7"],
  "report": "输出/T-0c21/填写核对.xlsx"
}
```

- 每项检查的值为 `passed`、`failed` 或 `skipped`。`skipped` 表示这项做不了（如没有 Excel 时的 `excel`），不算失败。
- 写入本身失败时返回 `CHECK_` 错误信封。
- 各项检查：
  - `readback`：重新打开写好的文件，每个写入格的值与计划一致；
  - `formulas`：受写入影响的公式按 Excel 规则在本地重算并写回缓存，读回一致、没有错误值；本地算不了的公式（不支持的函数、循环引用）去掉旧缓存、设置打开时重算，这时记为 `skipped`，`recalc` 列出这些格；
  - `crossFoot`：区域合计行的 `SUM` 公式与明细相符；明细整列来自一张结果表时，与查询算出的合计比较；
  - `untouched`：计划外的单元格、样式、公式、合并区域和其他包部件都没变；
  - `completeness`：区域里的待填位置都已填写或列为人工填写；
  - `excel`：本机有 Excel 时用它重算一遍并比较公式结果，没有 Excel 时 `skipped`。
- 返回里还有 `recalc`（需由 Excel 打开时重算的格）和 `problems`（不通过的检查各自的前几条原因）。
- `report` 是填写核对表，含"写入明细""核对""待人工填写""待重算公式"四张表。

**参数：**`{ "table": "D-002", "offset": 0, "limit": 200, "locate": 102, "columns": null }`

## 四、流程事件与前端命令（`audit-events/1`、`audit-app/1`）

### 4.1 事件信封

```json
{
  "v": "audit-events/1",
  "session": "S-41d2",
  "task": "T-0c21",
  "seq": 128,
  "ts": "2026-10-17T08:01:22.410Z",
  "type": "node.finished",
  "data": {}
}
```

- 每个事件都属于一个对话（`session`）；属于底稿任务的事件另带 `task`，纯对话事件没有 `task`。对话与任务的关系见 4.8。唯一的例外是全局的 `mcp.status`（4.10）。
- `seq` 在对话内严格递增。前端断线重连后用 `session.events` 从某个 `seq` 之后补取；`task.events` 是按任务筛选的同一序列。
- 事件只追加、不修改。状态由前端按事件累积，也可以用 `task.get` 取当前快照。

### 4.2 事件类型

| 类型 | 时机 | `data` 主要字段 |
|---|---|---|
| `task.created` | 任务登记 | 用户原话、附件快照、交付物 |
| `task.understood` | 需求理解完成 | 交付物、期间、范围、约束（原文）、拆分出的子任务 |
| `stage.changed` | 进入新阶段 | `stage`：`understand`、`workpaper`、`data`、`basis`、`confirm`、`compute`、`fill`、`notes`、`review` |
| `node.started` | 节点开始 | `node`、`kind`（`code`、`model`、`human`、`check`）、`region`（如有） |
| `node.progress` | 长节点进度 | `message`、`done`、`total`。暂不产生：dsh 不转发 MCP 的进度通知 |
| `node.finished` | 节点结束 | `outcome`：`passed`、`failed`、`skipped`；`refs`（产出的编号）；失败时可带 `reason` |
| `check.result` | 一项核对完成 | `check`、`passed`、`detail`（差额、样例）、`region`、`attempt`（区域第几次计算，从 1 起；无区域的核对为 1） |
| `node.retry` | 重做 | `attempt`、`reason`（上次失败原因原文） |
| `card.opened` | 需要用户处理 | 整张卡片（第五节） |
| `card.closed` | 卡片已答或撤回 | `card`、`answer` 或 `withdrawn`；任务的卡片带 `task` |
| `region.state` | 区域状态变化 | `region`、`state`（见 4.4） |
| `user.message` | 任务进行中用户补充的话 | `text`（原文）、`regions`（Agent 判断受影响的区域）、`reason`（判断理由） |
| `task.rerun` | 用户要求重跑 | `scope`（`regions`、`fromStage`）、`note`（修改说明）、`invalidated`（作废的结果编号） |
| `output.ready` | 产出文件就绪 | `output`（`O-` 编号）、`file`（路径）、`kind`、`checks`（核对摘要） |
| `task.blocked` | 无法继续 | `where`、`why`、`suggest`；应用退出导致的中断带 `paused: true`（1.2） |
| `task.resumed` | 暂停或阻塞的任务继续 | `from`（`paused` 或 `blocked`）、`stage`（当前阶段） |
| `task.finished` | 结束 | `status`：`completed`、`partial`、`cancelled`、`failed`；每项交付的状态 |

任务状态的全部取值：`running`、`paused`（等卡片）、`blocked`（4.2 的 `task.blocked`）、`completed`、`partial`、`cancelled`、`failed`。
| `message.*`、`tool.*` | 对话消息和工具调用 | 见 4.8 |
| `mcp.status` | 外部 MCP 服务连接状态变化 | 见 4.10 |

### 4.3 前端命令

请求格式 `{ "id": "…", "method": "…", "params": {} }`，响应 `{ "id": "…", "ok": true, "result": {} }` 或 `{ "ok": false, "error": { "code", "message" } }`。

| 命令 | 用途 |
|---|---|
| `settings.get` / `settings.save` | 请求地址、模型（多个时选择） |
| `secret.save` | 保存 API Key（宿主加密存储，不回传） |
| `connection.test` | 测试连接并返回探测结果 |
| `project.list` / `project.create` / `project.open` / `project.rename` / `project.remove` | 项目管理（项目对应本地文件夹；移除只从应用中移除，不删文件） |
| `files.add` / `files.list` | 向项目添加资料和底稿并生成快照；按项目列出（资料属于项目，不属于某个对话或任务，见 2.6） |
| `session.*`、`message.send` / `message.stop` | 对话（4.8）。通常经 `message.send` 由 Agent 判断是否登记底稿任务 |
| `mcp.*` | 外部 MCP 服务管理（4.10） |
| `privacy.status` / `app.info` / `logs.export` | 设置页"数据与安全""关于"（4.11） |
| `task.create` | 直接提交底稿任务（如在打开的底稿上点"开始填写"）：`session`、原话、文件快照 |
| `task.list` | 按项目列出任务：状态、交付物、创建和结束时间 |
| `task.get` | 当前状态快照（4.4） |
| `task.events` | 从某个 `seq` 之后补取事件 |
| `task.message` | 任务进行中补充一句话（4.6） |
| `task.cancel` | 停止任务 |
| `task.resume` | 从检查点继续 |
| `task.rerun` | 改口径后重跑（4.7） |
| `card.answer` | 回答卡片 |
| `outputs.list` | 按项目列出全部产出文件：来源对话、所属任务（如有）、类型、核对摘要、时间（见 4.9） |
| `sheet.view` | 取工作表网格（4.5） |
| `table.view` | 查看资料表或结果表（转调 `table_view`） |
| `cell.trace` | 查单元格来源（转调 `trace_cell`） |
| `output.open` | 用本机 Excel 打开产出文件 |

**事件推送：**宿主主动推送 4.2 的事件，前端不轮询。

**列表命令的返回：**

```json
{
  "project.list": [ { "project": "P-7f3a", "name": "某公司 2025 年报", "folder": "D:\\审计\\某公司2025", "lastActive": "2026-10-17T08:00:00Z" } ],
  "files.list": [ { "file": "F-9a1be04c77d2", "name": "应收账款底稿.xlsx", "kind": "workpaper", "sizeBytes": 48210, "addedAt": "2026-10-17T07:58:12Z", "sheets": ["封面", "应收账款"] } ],
  "outputs.list": [ { "output": "O-0001", "file": "输出/T-0c21/应收账款底稿-填写成果.xlsx", "name": "应收账款底稿-填写成果.xlsx", "kind": "workpaper",
                     "session": "S-41d2", "task": "T-0c21", "checks": { "passed": 18, "failed": 0 }, "at": "2026-10-17T08:03:10Z" } ]
}
```

- `project.create`、`project.open`、`project.rename` 返回同样结构的单个项目。
- `files.list` 的 `kind` 为 `workpaper`、`data`、`other`；`sheets` 只对 Excel 文件给出。
- `outputs.list` 的 `kind` 为 `workpaper`、`report`、`table`、`other`；对话产出没有 `task` 和 `checks`。

### 4.4 任务快照（`task.get`）

```json
{
  "task": "T-0c21",
  "session": "S-41d2",
  "status": "running",
  "blocked": null,
  "stage": "compute",
  "lastSeq": 128,
  "deliverables": [ { "kind": "workpaper", "file": "F-…", "status": "in_progress" } ],
  "regions": [
    { "region": "W-003#R5", "range": "应收账款!A5:E11", "type": "fixed_table", "purpose": "应收账款账龄分析", "headerRows": [5, 6], "totals": [11], "manual": ["应收账款!E7:E10"],
      "state": "checking", "attempt": 2, "refs": ["R-012"], "card": null },
    { "region": "W-003#R6", "range": "应收账款!A15:D20", "type": "fixed_table", "state": "awaiting_confirmation", "card": "C-005" }
  ],
  "openCards": ["C-005"],
  "outputs": []
}
```

- `outputs` 是这个任务已就绪的产出编号（`O-`）。
- `blocked` 在任务阻塞时为 `{ where, why, suggest }`，与 `task.blocked` 事件相同。
- 区域可以带 `reason`：失败或跳过的原因。
- 区域的 `range`、`type`、`purpose`、`headerRows`、`totals`（合计行行号）、`manual`（人工填写的格）与 `sheet.view` 的 `overlay.regions`（4.5）一致；还没识别出语义的区域没有 `purpose`。

**区域状态 `state`：**

| 状态 | 含义 |
|---|---|
| `pending` | 未开始 |
| `understanding` | 识别区域语义 |
| `awaiting_confirmation` | 等用户确认（理解卡、口径卡或差异卡） |
| `computing` | 计算中 |
| `checking` | 核对中 |
| `checked` | 核对通过，待写入 |
| `written` | 已写入并回读通过 |
| `manual` | 整个区域留给人工 |
| `failed` | 重做用尽，阻塞 |
| `skipped` | 不需填写 |

前端按 `state` 给区域着色。状态变化同时以 `region.state` 事件推送。

### 4.5 工作表网格（`sheet.view`）

**参数：**

```json
{
  "file": "F-…",
  "sheet": "应收账款",
  "range": "A1:K60",
  "overlay": { "workpaper": "W-003", "plan": "FP-…", "output": null }
}
```

- `file` 可以是任何已添加的 Excel 文件，底稿和资料都可以。
- `range` 用于分块加载，单次最多 5,000 格。
- `overlay` 可选：
  - `workpaper`：叠加区域边界和区域状态；
  - `plan`：叠加写入计划，每格返回拟写值、来源编号、是否覆盖（转调 `fill_preview`）；
  - `output`：叠加已写入标记，点格可查来源。

**返回：**

```json
{
  "sheet": "应收账款",
  "sheets": [ { "name": "封面" }, { "name": "应收账款" }, { "name": "旧版", "hidden": true } ],
  "usedRange": "A1:K60",
  "range": "A1:K60",
  "freeze": { "rows": 6, "cols": 1 },
  "cells": [
    { "cell": "A1", "value": "应收账款明细表", "valueType": "string", "text": "应收账款明细表", "formula": null,
      "style": { "bold": true, "align": "center" } },
    { "cell": "C7", "value": "1200000.00", "valueType": "number", "text": "1,200,000.00", "numFmt": "#,##0.00", "formula": null },
    { "cell": "C12", "value": "1835000.00", "valueType": "number", "text": "1,835,000.00", "numFmt": "#,##0.00", "formula": "=SUM(C7:C11)" },
    { "cell": "F7", "value": "0.6539", "valueType": "number", "text": "65.39%", "numFmt": "0.00%", "formula": "=C7/$C$12",
      "plan": { "value": "0.6812", "stale": false } },
    { "cell": "D7", "value": "350000.00", "valueType": "number", "text": "350,000.00", "numFmt": "#,##0.00", "formula": null,
      "written": { "from": "R-014#1", "task": "T-0c21" } }
  ],
  "merges": ["A1:K1"],
  "rowHeights": { "1": 24 },
  "colWidths": { "A": 18 },
  "overlay": {
    "regions": [
      { "region": "W-003#R5", "range": "A5:H30", "type": "fixed_table", "purpose": "应收账款账龄分析",
        "headerRows": [5, 6], "totals": [30], "manual": ["H7:H29"], "state": "written" }
    ]
  }
}
```

- 表格在应用里只读，没有改单元格的命令。改内容只能通过任务写入新文件（3.8）。
- **整表信息：**`sheets` 是这个文件的全部工作表（按文件中的顺序，隐藏的带 `hidden: true`）；`usedRange` 是整张表的使用范围，前端据此分块加载；`freeze` 是文件里的冻结窗格（冻结的行数、列数），没有冻结时省略。`sheet` 参数省略时打开文件的活动工作表。
- **样式：**`style` 只在和默认不同时出现，字段有 `bold`、`italic`、`align`（`left`、`center`、`right`）、`wrap`、`fill`（底色，`#RRGGBB`，主题色由宿主换算成具体颜色）。前端至少用加粗、对齐和换行；边框和字体等不返回。
- **单元格坐标：**`cells`、`merges` 和 `overlay` 里的坐标都不带工作表名（返回只涉及一张表）。
- **`overlay.workpaper`：**`overlay.regions` 列出与本表有关的区域：`range`、`type`（3.2）、`purpose`、`headerRows`、`totals`（合计行行号）、`manual`（人工填写的格或范围），以及 4.4 的当前 `state`。
- **`overlay.output`：**打开产出文件时，由任务写入的格带 `written: { from, task }`，`from` 是来源（结果行编号），点格用 `cell.trace` 查完整来源。没写入的格不带 `written`。
- **公式和值都返回：**`formula` 是公式原文（以 `=` 开头，无公式为 `null`），`value` 是文件里保存的缓存值。前端默认显示值，可以切换成显示公式，选中单元格时在编辑栏位置显示公式。
- 共享公式、数组公式都展开成每格各自的公式文本，前端不用自己推算。数组公式另带 `array: "F7:F11"`，标出整块范围。
- 文件里没有缓存值的公式格（例如程序生成后没在 Excel 里打开保存过），`value` 为 `null`，带 `stale: true`。
- **叠加写入计划时**（`overlay.plan`）：
  - 拟写格的 `plan` 带拟写值、来源编号、是否覆盖（来自 `fill_preview`）；
  - 依赖拟写格的公式格（直接或间接引用），`plan.value` 是代入拟写值重算后的值；
  - 宿主把计划写进临时副本，用和填写阶段相同的方式（本机 Excel）重算后读回；
  - 重算做不到时（没有 Excel、超时、引用了其他工作簿），这些格标 `plan.stale: true`、不带 `plan.value`，前端显示"待重算"，不显示旧值。

### 4.6 任务中补充（`task.message`）

**参数：**`{ "task": "T-0c21", "text": "D 列用本年期初" }`

- 宿主把原话作为固定锚点追加给任务，编排插件判断它影响哪些区域：
  - 影响尚未计算的区域：直接作为口径依据（`basis: user`）；
  - 影响已计算或已写入的区域：生成一张口径确认卡，说明要重做哪些区域，确认后按 4.7 重跑。
- 推送 `user.message` 事件。

### 4.7 重跑（`task.rerun`）

**参数：**

```json
{
  "task": "T-0c21",
  "scope": { "regions": ["W-003#R5"], "fromStage": "basis" },
  "note": "账龄改从发票日期起算"
}
```

- `regions` 为空表示整个任务；`fromStage` 取 4.2 `stage.changed` 的阶段名。
- 重跑生成新的结果编号，旧编号标为作废，旧产出文件保留。
- `note` 作为用户口径（`basis: user`）进入重跑的区域。
- 推送 `task.rerun` 事件，之后照常推送各节点事件。

### 4.8 对话与通用能力

界面以底稿为中心，同时保留通用对话：没打开底稿时对话占满中间；涉及底稿时底稿居中，对话收到右侧。以后 Agent 还可能操作内部系统。

**对话和任务的关系：**
- 一个对话（`S-`）由多轮消息（`M-`）组成，对应 Harness 的一个会话。
- 某一轮如果要填底稿，就在这个对话里登记一个底稿任务（`T-`），按第三节的流程推进；任务的事件带 `task`，和对话事件在同一序列里。
- 其他轮是自由对话：问答、查数、临时分析、调用内部系统，不产生任务。
- 一个对话可以有多个任务；任务进行中用户在同一对话里说的话，宿主判断是补充给任务（按 4.6 处理）还是普通对话。用户明确指向任务时，前端直接用 `task.message`。

**命令：**

| 命令 | 参数与返回 |
|---|---|
| `session.list` | 按项目列出对话：`[ { session, project, title, lastActive, tasks: [ { task, status } ], openCards } ]`，`openCards` 是未处理卡片数 |
| `session.create` | `{ project, title? }` → `S-` |
| `session.get` | 对话快照：消息列表（分页）、所含任务的快照（4.4）、未处理的卡片 |
| `session.rename` / `session.delete` | 删除只删应用中的记录，项目文件夹里的产出不删 |
| `session.events` | 从某个 `seq` 之后补取事件 |
| `message.send` | `{ session, text, files? }` → `M-`。`files` 是项目资料的 `F-` 编号；新文件先用 `files.add` 加入项目。是否产生底稿任务由 Agent 判断；产生时推送 `task.created` |
| `message.stop` | 停止当前这一轮回复（不影响后台进行中的底稿任务） |

**对话事件：**

| 类型 | 时机 | `data` 主要字段 |
|---|---|---|
| `message.created` | 用户消息登记 | `message`、原文、附件 |
| `message.delta` | 回复流式片段 | `message`、`text`（增量文字） |
| `message.completed` | 一轮回复结束 | `message`、全文、`refs`（引用的结果、产出编号） |
| `tool.started` | 工具调用开始 | `call`、`tool`（名称）、`system`（所属系统，如"审计工具""OA"）、`argsSummary`（一行参数摘要）、`region`（编排插件调用时，如有） |
| `tool.finished` | 工具调用结束 | `call`、`ok`、`resultSummary`（一行结果摘要）、`refs`、`durationMs` |

- 工具事件覆盖所有工具，不限于审计工具。第三节由编排插件调用的工具由编排插件自己推送，带 `task`，按区域调用时带 `region`。
- 摘要由宿主从工具结果生成，不含全量数据；要看全部内容用 `table.view` 或 `sheet.view` 打开 `refs`。

**和 Harness 的对应（宿主负责转换，前端只认上面的结构）：**

| 本文 | Harness（桥接插件，见 1.1） |
|---|---|
| `message.delta` | `assistant.stream` 通知，`frame.chunk.type` 为 `text-delta` 时取 `text` |
| `message.completed` | `session.event` 中的 `assistant/message`（本轮以 `turn/end` 结束） |
| `message.created` | `session.event` 中的 `user/message` |
| `tool.started`、`tool.finished` | `session.event` 中的 `tool/call`、`tool/result` |
| `message.send` | `session/prompt` |
| `message.stop`、`task.cancel` | `session/cancel`（本轮结束原因 `aborted`） |
| `task.resume`（崩溃后） | `session/resume` |
| `task.*` 命令、`cell.trace`、`table.view` | 1.2 的 `task/*` 和 `audit/tool` 请求；流程事件来自 `task.event` 通知 |
| 动作确认卡（5.8） | `approval.request` / `approval.closed` 通知；回答转成 `approval/respond`：`confirm` → `allowed-once`，`reject` → `rejected` |
| 一般追问（5.6） | 模型调用 `ask_user_question` 产生的 `question.request` / `question.closed`；回答转成 `question/respond` |
| 编排卡片（5.2～5.5、5.7） | `card.opened` / `card.closed`；回答转成 `card/answer` |
| 对话产出 | 轮次交付物（`deliverables`）和工具产出文件 |

**工具事件里的名字：**
- 内置审计工具：`tool` 为 `mcp__audit__<工具名>`，`system` 填"审计工具"。
- 外部 MCP 服务的工具：`tool` 为 `mcp__<服务名>__<工具名>`，`system` 填服务的 `title`（4.10）。

### 4.9 对话产出

- 对话中产生的表格或文件（结果表导出、临时分析的 Excel、查询结果）登记为产出文件 `O-`，推送 `output.ready`（带 `session`，可无 `task`）。
- `sheet.view` 的 `file` 和 `table.view` 的 `table` 都接受 `O-` 编号：Excel 产出用 `sheet.view` 打开，CSV 或结果表用 `table.view` 打开，都显示在中间区域。
- `outputs.list` 列出项目内全部产出，包括对话产出和底稿任务产出，带所属对话和任务。

### 4.10 外部 MCP 服务

内部系统通过 MCP 接入：能做成 MCP 服务的系统，在设置里添加后 Agent 就能调用。应用先具备 MCP 能力，具体接哪些系统按实际情况定。

**范围：**
- 这里只管用户添加的外部服务。内置的审计工具服务（第三节）随应用启动，不在设置里出现，也不能删除或停用。
- 服务是全局设置，所有项目和对话共用。
- 宿主为用户添加的服务生成一个额外的配置层，每个启用的服务一条 `dsh-mcp-client` 配置，启动 Harness 时用 `--patch` 叠在我们的配置层上。改了服务设置后，宿主重启当前项目的 Harness 进程使其生效。
- `sideEffect: mutating` 的工具名写进 `confirmTools`（支持 `前缀*`；以 `!` 开头的是排除项，例如 `["mcp__oa__*", "!mcp__oa__query_*"]`），调用时由桥接插件发 `approval.request`，宿主转成 5.8 的动作确认卡。
- 设置里停用的工具（`enabled: false`）写进启动参数 `disabledTools`（环境变量 `AUDIT_DISABLED_TOOLS`，写法与 `confirmTools` 相同）：这些工具对模型隐藏，调用会被拦下。名单在 Harness 启动时读入，改动后和服务配置改动一样要重启 Harness。
- 模型看到的工具名是 `mcp__<服务名>__<工具名>`，所以服务名只能用字母、数字和下划线，并且唯一。`audit` 留给内置审计工具服务，不能使用。

**服务的两种接法：**

```json
{
  "name": "oa",
  "title": "OA 系统",
  "enabled": true,
  "transport": "stdio",
  "command": "C:\\tools\\oa-mcp\\oa-mcp.exe",
  "args": ["--profile", "prod"],
  "env": { "OA_REGION": "hq" },
  "secretEnv": ["OA_TOKEN"]
}
```

```json
{
  "name": "contract",
  "title": "合同系统",
  "enabled": true,
  "transport": "http",
  "url": "https://contract.intra.example/mcp",
  "hasToken": true
}
```

- `stdio`：本机程序，填命令、参数、环境变量。
- `http`：远程地址，填 URL 和令牌。令牌以 `Authorization: Bearer` 头发送。
- 令牌和敏感环境变量都走宿主的加密存储，读取时不回传原文：`http` 服务只返回 `hasToken`，`stdio` 服务的敏感变量只返回变量名（`secretEnv`）。
- 未修改的令牌在 `mcp.update` 中省略即可，宿主保留原值。

**命令：**

| 命令 | 参数与返回 |
|---|---|
| `mcp.list` | 全部外部服务：上面的配置（不含令牌原文）、连接状态、工具清单 |
| `mcp.add` | 服务配置；`http` 服务另带 `token`，`stdio` 服务另带 `secrets: { 变量名: 值 }` → 保存并尝试连接 |
| `mcp.update` | `{ name, …要改的字段 }`；也用于改工具属性：`tools: [ { tool, enabled?, sideEffect? } ]` |
| `mcp.remove` | `{ name }`，同时删除它的令牌 |
| `mcp.test` | `{ name }`，或未保存的配置（添加前试连）→ 连接结果和工具清单 |

`mcp.test` 返回：

```json
{
  "ok": true,
  "serverInfo": { "name": "oa-mcp", "version": "1.4.0" },
  "latencyMs": 180,
  "tools": [
    { "tool": "query_expense", "description": "按单号或日期查询报销单", "argsSummary": "billNo?, from?, to?", "enabled": true, "sideEffect": "readonly" },
    { "tool": "approve", "description": "审批报销单", "argsSummary": "billNo, opinion", "enabled": true, "sideEffect": "mutating" }
  ]
}
```

- 连接失败时 `ok: false`，带 `error: { code, message }`。`code` 取 `MCP_SPAWN_FAILED`（程序启动不了）、`MCP_UNREACHABLE`（地址连不上）、`MCP_AUTH`（令牌无效）、`MCP_PROTOCOL`（不是 MCP 服务或版本不兼容）、`MCP_TIMEOUT`。
- `argsSummary` 由宿主从工具的参数 schema 生成，`?` 表示可选。

**工具属性：**
- `enabled`：停用的工具不交给模型（经 `disabledTools` 传给 Harness，见上）。默认启用。
- `sideEffect`：`readonly` 或 `mutating`。默认 `mutating`，由用户在设置里改。`mutating` 的工具每次调用都走 5.8 动作确认卡，`readonly` 的直接调用。
- 服务端新出现的工具按默认值处理（启用、`mutating`）。服务端消失的工具，属性保留，不再显示。
- MCP 工具自带的 `readOnlyHint` 等标注只用来在设置里给出建议，不直接生效。

**事件：**

| 类型 | 时机 | `data` 主要字段 |
|---|---|---|
| `mcp.status` | 服务连接状态变化 | `name`、`state`（`connecting`、`connected`、`failed`、`disabled`）、`error`（`code`、`message`，失败时）、`toolCount` |

- `mcp.status` 是全局事件，不属于某个对话，信封里没有 `session` 和 `task`，也不占对话的 `seq`。前端在设置页和左栏底部显示。
- 对话中调用外部工具时，`tool.started` 的 `system` 填服务的 `title`。

## 五、界面卡片（`audit-cards/1`）

### 5.1 卡片通用结构

```json
{
  "card": "C-004",
  "kind": "workpaper_understanding",
  "task": "T-0c21",
  "title": "请确认对底稿的理解",
  "blocking": true,
  "body": {},
  "actions": ["confirm", "edit", "reject"],
  "defaultAction": "confirm"
}
```

- `blocking: true` 表示流程等这张卡；`false` 表示其他区域照常进行，只有相关区域等待。
- **回答格式：**`card.answer` 提交 `{ "card": "C-004", "action": "confirm", "edits": {}, "note": "" }`。
- 卡片回答后不可修改。改主意时用 `task.message` 或 `task.rerun`（4.6、4.7），生成新卡片。

### 5.2 底稿理解卡 `workpaper_understanding`

```json
{
  "workpaper": "W-003",
  "template": { "fingerprint": "TPL-…", "known": false },
  "regions": [
    {
      "region": "W-003#R5",
      "range": "应收账款!A5:H30",
      "type": "fixed_table",
      "purpose": "应收账款账龄分析",
      "columns": [
        { "col": "C", "measure": "期末余额", "period": "2025-12-31", "unit": "元", "direction": "debit",
          "basis": "template", "basisRef": "应收账款!C5", "confidence": "high" }
      ],
      "manual": ["应收账款!H7:H29"],
      "uncertain": [
        { "item": "D 列期间", "options": ["上年期末", "本年期初"], "suggest": 0, "why": "表头只写“期初”" }
      ]
    }
  ]
}
```

前端用 `sheet.view` 显示底稿，按 `range` 高亮各区域；点区域显示其语义。`type` 取 3.2 的区域类型，修改时可以改成别的类型或 `none`。`uncertain` 里的每一项都是一个选择题。

**修改（`action: "edit"`）时 `edits` 的格式：**

```json
{
  "uncertain": { "W-003#R5/D 列期间": 1 },
  "regions": [
    { "region": "W-003#R5", "type": "detail_table", "range": "应收账款!A5:H32" },
    { "region": "W-003#R5", "columns": [ { "col": "D", "measure": "期初余额", "period": "2025-01-01", "unit": "元", "direction": "debit" } ] },
    { "region": "W-003#R7", "type": "none" },
    { "add": { "range": "应收账款!A40:F48", "type": "fixed_table", "purpose": "坏账准备计提" } }
  ],
  "manual": { "add": ["应收账款!C12"], "remove": ["应收账款!H7"] }
}
```

- `uncertain`：键为"区域编号/项目名"，值为所选选项的序号，或一段文字。
- `regions`：每项改一个区域，只写要改的字段；`type: "none"` 表示该区域不填；`add` 新增一个代码没识别出的区域。
- `manual`：标记或取消人工填写的单元格。
- 修改过的区域由代码重新校验（`workpaper_semantics_check`），不通过时退回这张卡并标出错误。确认后的修改依据记为 `user`。
- 退回时卡片 `body` 带可选的 `errors`（`workpaper_semantics_check` 的错误清单），前端在对应区域标出。

### 5.3 口径确认卡 `basis_confirmation`

用于依据为 `inferred` 且影响结果的口径，一张卡最多 3 个问题。另外用于两种情况：
- 两路复算不一致、编排又判断不了哪一路对时，请用户选算法；
- 任务中补充的话（4.6）影响已算完的区域时，确认是否重跑。

```json
{
  "questions": [
    {
      "id": "q1",
      "region": "W-003#R5",
      "text": "账龄从哪一天开始算？",
      "options": [
        { "label": "凭证日期", "impact": "1年以内合计 1,200,000.00" },
        { "label": "发票日期", "impact": "1年以内合计 1,150,000.00" }
      ],
      "suggest": 0,
      "allowText": true
    }
  ]
}
```

- `impact` 由代码算出，模型不写数字。
- 回答：`{ "action": "confirm", "edits": { "q1": 0 } }` 或自由文字。

### 5.4 差异卡 `discrepancy`

控制数或双路复算不一致，且自动重做后仍未解决时出这张卡。

```json
{
  "region": "W-003#R5",
  "check": "control",
  "left": { "label": "账龄合计", "value": "1834500.00", "ref": "R-012" },
  "right": { "label": "余额表 1122 期末", "value": "1835000.00", "ref": "D-001" },
  "diff": "-500.00",
  "threshold": "1000.00",
  "candidates": [ { "label": "第 102 行金额无法解析（“12万”）", "ref": "D-002#102" } ],
  "actions": ["accept_with_note", "fix_data", "stop"]
}
```

可选字段：`reason`（重做后仍未解决的原因说明）。

### 5.5 写入确认卡 `write_confirmation`

```json
{
  "plan": "FP-…",
  "target": "应收账款底稿.xlsx",
  "output": "输出/T-0c21/应收账款底稿-填写成果.xlsx",
  "regions": [ { "region": "W-003#R5", "cells": 96, "sources": ["R-012"], "basis": "凭证日期起算；单位元" } ],
  "manual": ["应收账款!H7:H29"],
  "overwrites": [],
  "expand": [],
  "actions": ["confirm", "reject"]
}
```

`expand` 可选：明细表需要扩展的行（来自 `fill_compile`），有时前端提示"将插入若干行"。

前端用 `sheet.view` 加 `overlay.plan` 在表上预览每格拟写值和覆盖位置，用户看过再确认。

### 5.6 一般追问 `question`

需求不清时使用，最多 3 个问题，结构与 5.3 相同，不带 `region` 和 `impact`。

资料有 `DATA_` 问题（如无法解析的值）时，编排插件也发这张卡，问是排除无效值所在的行继续导入，还是不用这张表；`body.error` 带工具返回的错误（2.4）。

### 5.7 结果卡 `result_summary`

```json
{
  "outputs": [ { "output": "O-0001", "file": "输出/T-0c21/应收账款底稿-填写成果.xlsx", "kind": "workpaper" } ],
  "checks": { "passed": 18, "failed": 0, "retried": 1 },
  "manual": 4,
  "notes": [ { "section": "审计说明", "text": "…", "status": "suggested" } ],
  "computedBy": "code",
  "suggestedBy": ["notes"]
}
```

- 可选字段：`failed`（未完成的交付及原因，任务状态为 `partial` 时给出）。
- **核对计数：**按"核对项 + 区域"取最新一次（`attempt` 最大的那次）计数。`retried` 是之前失败、重做后通过的项数。进度卡和结果卡用同一口径。
- `outputs` 每项带 `output`（`O-` 编号），前端用它打开。
- 前端区分"代码算出的结果"和"模型给出的建议"（09 §二.6）：数字区来自 `computedBy: code`，`notes` 中 `status: suggested` 的文字标为建议，审计人员确认后才算定稿。

### 5.8 动作确认卡 `action_confirmation`

Agent 对外部或内部系统做有副作用的操作（提交、审批、写入、发送、删除）之前，必须出这张卡，用户确认后才执行。只读查询不出卡。

```json
{
  "card": "C-009",
  "kind": "action_confirmation",
  "session": "S-41d2",
  "title": "确认提交报销审批",
  "blocking": true,
  "body": {
    "system": "OA",
    "operation": "提交审批",
    "target": "报销单 BX-2025-1188",
    "argsSummary": [
      { "label": "审批意见", "value": "同意" },
      { "label": "金额", "value": "3,260.00" }
    ],
    "reversible": false,
    "reverseHow": null,
    "tool": "mcp__oa__approve",
    "call": "call_7"
  },
  "actions": ["confirm", "reject"],
  "defaultAction": "reject"
}
```

- 哪些操作有副作用不由模型判断：外部 MCP 服务的工具按用户在设置里标的 `sideEffect`（4.10），默认 `mutating`；内置审计工具由代码声明。`mutating` 的工具每次调用都出这张卡，`readonly` 的直接调用。
- 卡片字段由宿主从 `approval.request`（工具名、调用编号、参数）和工具清单生成：`system` 为服务的 `title`，`operation` 取工具说明，`argsSummary` 由参数生成，`call` 为调用编号。`target`、`reversible` 取不到时为 `null`，前端按不可撤销处理。
- 不可撤销的操作（`reversible: false` 或 `null`），默认按钮是拒绝。
- 每次操作单独确认，确认只对这一次调用有效，和 Harness 审批机制的"允许一次"一致。
- 回答为 `confirm` 后宿主放行这次调用；`reject` 时工具返回"用户拒绝"，Agent 据此继续对话。
- 底稿写入用 5.5 的写入确认卡，不用这张卡。

## 七、变更规则

- 接口改动先改本文，版本标识的末位数字加一（如 `audit-cards/1` → `audit-cards/2`）。
- 只增加可选字段，不改版本号；删除或改变字段含义，必须升版本，并在宿主保留一个版本的兼容。
- 每份接口有一组样例（第六节的回放文件和工具样例），改动时同步更新。
