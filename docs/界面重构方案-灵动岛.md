## 0. 这次要解决的真实矛盾

上一版方案的方向是「减装饰、去玻璃、去发光」，这套语言适合**静态的阅读界面**，但和你要的
灵动岛是冲突的：孤立的液态玻璃动画放在一片哑光平面里，只会显得突兀。

真正的解法不是把两边都做一半，而是**引入「材料层级」概念**：

| 层级 | 材料 | 承载什么 | 行为 |
| --- | --- | --- | --- |
| L0 底 | 哑光平面（无模糊、无阴影） | 会话列表、消息正文、设置页 | 恒定、不参与动画 |
| L1 面 | 实心卡片（一档边框） | 任务卡、结果预览、表单 | 只做 120ms 背景过渡 |
| L2 浮 | **液态玻璃** | 灵动岛、菜单、命令面板、Toast | 可移动、可形变、有空间动效 |

玻璃不是装饰，而是**信号**：它只出现在「正在发生的事」上。全应用同时最多 1–2 处玻璃，
其余 95% 的面积保持哑光。这样灵动岛既高级，又不会变成 SaaS 落地页。

## 1. 灵动岛：锚定在 Composer 上的按需面板

### 1.1 位置与显形策略（核心决策）

先排除两个都不成立的选项：

| 选项 | 为什么不成立 |
| --- | --- |
| **常驻 268px 通道** | 90% 时间是**空地**而非留白。用户会持续注意到一块什么都没有的区域；缩成 44px 图标条只是把空地变小，问题还在 |
| **悬浮覆盖消息列** | 浮层压在可滚动内容上、不与任何边缘对齐，读起来像贴纸不像空间分层；正文从它下方穿过是持续的分心源 |

两者共同的错误假设是「通道必须一直存在」。动态岛成立的前提恰恰是**不在时占零面积**。

**定案：岛锚定在 Composer 右端，按需显形。**

```
空闲（占 0px，与无岛时完全一致）
┌──────────┬────────────────────────────────────────────────┐
│ Sidebar  │  Topbar                                        │
│  248px   ├────────────────────────────────────────────────┤
│          │                                                 │
│          │        消息列（max 700px，几何居中）              │
│          │                                                 │
│          │        ── Composer ──────────────────           │
└──────────┴────────────────────────────────────────────────┘

工具活跃（岛从 Composer 右端长出，侧栏不动）
┌──────────┬────────────────────────────────────────────────┐
│ Sidebar  │  Topbar                                        │
│  248px   ├────────────────────────────────────────────────┤
│          │                                                 │
│          │     消息列（max 700px，左移 88px）    ┌────────┐ │
│          │                                     │ ● 执行 │ │
│          │                                     └────────┘ │
│          │                                     ┌────────┐ │
│          │                                     │ ✓ 完成 │ │
│          │                                     └────────┘ │
│          │        ── Composer ──────────       ╰─┤        │
└──────────┴────────────────────────────────────────────────┘
                                              ↑ 岛的下沿贴住 Composer
```

关键几何：

- **锚点**：岛栈的底部与 Composer 顶部对齐，水平方向与 Composer 右端对齐。
  它是「从输入框长出来的」，不是「浮在页面上的」——这是它不显得突兀的根本原因。
- **宽度**：`232px`，只占消息列右侧的留白区，**不覆盖正文**。
  消息列 `max 700px` 在 `1400px` 宽的窗口里本来就有富余空白，岛用这块空白。
- **消息列不重排**：岛显形时消息列**不平移、不缩放**。
  正文的 `max-width` 和居中位置都不变，岛落在它右侧的既有空白里。
  只有当窗口 < 1180px（右侧空白不足 232px）时，消息列才左移，此时用
  `transition: transform 240ms` 平滑让位，而不是硬跳。
- **滚动位置不变**：岛在消息流之外，`position: absolute` 相对 workspace，
  完全不参与消息区的滚动容器。

### 1.2 三级降级

| 窗口宽度 | 岛形态 | 消息列 |
| --- | --- | --- |
| ≥ 1180px | 完整岛栈，`232px`，贴 Composer 右端 | 不动 |
| 900–1180px | 岛栈收窄至 `200px`，动作行省略 | 左移 24px |
| < 900px | 降级为 Composer 上方的**单行状态条**（高 32px），只显示当前活跃的那一个 | 不动 |

窄屏降级不是缩小岛，而是**换一种形态**：一行动态状态条
（`◐ 正在校验借贷平衡 · 2/5`）比一个挤扁的卡片可读得多。

### 1.3 岛的堆叠方向：向上

岛锚在 Composer 上，所以它**向上生长**：

- 新的岛在**最下方**（紧贴 Composer），已完成的向上推走
- 理由：视线自然落在 Composer 附近，「正在执行的那个」应该离输入框最近；
  已完成的历史向上沉淀，越旧越远，不需要用户主动忽略
- 已有的岛被向上推时，走 §1.6 的 FLIP 补偿，视觉上是「被顶上去」而非「整体跳一下」
- 超出可视高度的岛淡出（`opacity → .35`）并停止参与 FLIP，避免长列表拖慢动画

### 1.4 岛的滚动与溢出

- 岛栈自身**可滚动**（`overflow-y: auto`，滚动条默认隐藏，hover 才显细条）
- 栈高上限 = Composer 顶部到 Topbar 之间的可用高度 − 24px
- 超过 5 个已完成岛时，最早的 3 个自动折叠为一行：
  `✓ 3 个已完成工具`（可点击展开），保持栈的总高度可控
- **栈的滚动与消息流滚动完全独立**，滚岛不影响消息区


### 1.5 岛的状态机

一个岛 = 一次工具调用（`toolCalls` 里的一条记录）。状态与现有后端字段一一对应，
**不需要新增任何 IPC**：

| 岛状态 | 触发条件（现有数据） | 视觉 | 尺寸 |
| --- | --- | --- | --- |
| `idle` | 无 running 调用 | 岛不出现，占 0px | 0 |
| `pending` | `call.status === 'running'` 且刚开始 | 左侧脉冲圆点 + 工具名 | 40px |
| `active` | `running` + 有参数/进度 | 展开：工具名 + 当前动作 + 进度条 | 76px |
| `success` | `status === 'succeeded'` | 收缩为一行：✓ + 工具名 + 耗时 | 34px |
| `error` | `status === 'failed'` | 红环 + 一行错误摘要 + 「重试」 | 34px |
| `cancelled` | `status === 'cancelled'` | 灰色 + 「已停止」 | 34px |
| `expired` | 整批结束且用户未展开 | 折叠为顶部汇总 chip | 0 |

状态来源全部是 `session.get` 已返回的 `calls[]`：
`{ id, label, status, result, finishedAt }`（`service.mjs:117` 写入）。

### 1.6 「灵动岛」式展开 / 收缩 / 上移

这正是你描述的核心动画，拆成三段：

**① 展开（调用开始）**

```
基线位置                    展开后
  │                          ┌──────────────────┐
  │                          │ ◐ 执行本地审计    │  ← 从 40px 高胶囊
  │  ┌─────────┐             │ 正在校验借贷平衡  │     展开到 76px
  │  │ ◐ 执行… │     →       │ ▓▓▓▓▓░░░░░ 42%   │
  │  └─────────┘             └──────────────────┘
```

- 从 Composer 右端「长出」：`transform-origin: right center`，
  `scaleX(.92) → 1` + `translateX(8px) → 0`，220ms `--ease-island`。
- 玻璃边缘的**高光带**沿边框扫过一圈（`--sheen` 变量位移），260ms，只播一次。
- 高度用 `grid-template-rows: 0fr → 1fr` 或固定高度过渡，**不用 `height: auto`**，
  保证 60fps。

**② 收缩（调用结束）**

- 内容淡出 80ms → 高度收拢 180ms → 变为 34px 完成态。
- 完成瞬间有一次「落定」：`scaleY(.96) → 1`，无弹跳，`--ease-island`。

**③ 上移一个单位（下一个调用开始）**

这是关键，用 **FLIP** 而不是重新排列 DOM 顺序：

1. 新岛插到岛栈**底部**，已有岛向上推（方向见 §1.3）。
2. 记录所有已有岛的位置 → 应用新布局 → 计算 `deltaY` →
   反向 `translateY(deltaY)` 后过渡到 0。
3. 移出屏幕的岛用 `opacity` 淡出，**不缩小到 0**，避免「消失得突兀」。

```ts
// 伪代码：岛栈内的 FLIP
const prev = new Map(items.map(el => [el.id, el.getBoundingClientRect().top]));
applyNewOrder();
for (const el of items) {
  const dy = prev.get(el.id)! - el.getBoundingClientRect().top;
  if (dy) el.animate(
    [{ transform: `translateY(${dy}px)` }, { transform: 'none' }],
    { duration: 320, easing: 'cubic-bezier(.22,1,.36,1)' }
  );
}
```

320ms 是刻意比其他动效长的——**上移是空间位移，需要被感知到**；
hover 仍然是 120ms，两者不冲突。

### 1.7 内容映射：让岛说的是人话

现在 `toolLabels`（`model-tools.mjs:13`）只给了 5 个本地工具的粗标签。
岛需要三层文案：

| 层级 | 示例 | 来源 |
| --- | --- | --- |
| 工具名 | 执行本地审计 | `call.label` |
| 当前动作 | 正在校验借贷平衡 | `timeline.phase`（已存在） |
| 结果摘要 | 1,240 行 → 38 条异常 · 1.8s | `call.result` |

工具名按 `call.name` 细分（现有 `step.name` 已写入 `toolCalls.name`）：

```
list_local_files   → 浏览文件        → 已在项目内查找文件 · 命中 12 个
preview_local_file → 读取文件内容    → 已读取 销售明细.xlsx · 4 列
get_audit_tools    → 选择审计工具    → 匹配到「凭证校验」
run_audit_tool     → 执行本地审计    → 1,240 行 → 38 条异常
get_task_result    → 读取执行结果    → 已取回结果 · 前 50 行
legacy_*           → 原版 MCP · xxx  → 沿用同上结构
```

这些映射放在一个 `src/client/toolNarrative.ts` 里，是纯展示层，不碰业务逻辑。

### 1.8 顺序与并发

- **顺序**：新岛在**最下方**（紧贴 Composer），已完成的**向上**沉降，
  与 §1.3 一致。理由：视线自然落在 Composer 附近，正在执行的那一条离输入框最近；
  已完成的历史向上沉淀，越旧越远。
- **并发**：多个岛同时 `active` 时垂直堆叠，每个保持独立生命周期。
  超过 3 个 active，第 4 个起折叠为「+2 个并行任务」的一行，点击展开。
- **整批结束**：全部完成后 2s，自动折叠为一个汇总 chip：
  `✓ 5 个工具 · 3.4s · 2 条异常`，点击可重新展开全部岛。这是 `expired` 态。

### 1.9 中断 / 重试 / 重新发送 / 分支（每模块自由度）

| 操作 | 当前状态 | 落点 |
| --- | --- | --- |
| **中断** | 已有 `chat.cancel` + `task.cancel` | 岛 active 态内联「停止」按钮；任务卡保留原有停止 |
| **重试** | 已有 `task.retry` | 岛 error 态内联「重试」；成功后原岛**原地复活**而非新建 |
| **重新发送** | 已有 `retryMessage`（Messages.tsx:77） | 从「错误消息下方」提到**消息 hover 菜单**（编辑 / 重新发送 / 复制） |
| **分支** | **缺失，需新增** | 消息 hover 菜单「从此处分叉」→ 见下 |

## 2. 液态玻璃：可控实现（不引入依赖）

规范禁止新增 UI 库，全部用 CSS + 原生 Web Animations API 实现。

```css
.island {
  position: relative;
  border-radius: 22px;
  /* 玻璃主体 */
  background: linear-gradient(
    145deg,
    rgba(255,255,255,.78) 0%,
    rgba(255,255,255,.62) 45%,
    rgba(255,255,255,.72) 100%
  );
  backdrop-filter: blur(20px) saturate(180%);
  -webkit-backdrop-filter: blur(20px) saturate(180%);
  box-shadow:
    0 1px 1px rgba(15,23,42,.04),
    0 6px 20px rgba(15,23,42,.07),
    inset 0 1px 0 rgba(255,255,255,.85);   /* 顶边内高光 */
}

/* 液态边缘：用 mask 做渐变描边，避免 border 的硬边 */
.island::after {
  content: ''; position: absolute; inset: 0;
  border-radius: inherit; padding: 1px;
  background: linear-gradient(
    140deg,
    rgba(255,255,255,.9),
    rgba(91,91,214,.22) 35%,
    rgba(255,255,255,.35) 60%,
    rgba(91,91,214,.14)
  );
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor; mask-composite: exclude;
  pointer-events: none;
}

/* 高光扫过：只在 expand 时播一次 */
.island.expanding::before {
  content: ''; position: absolute; inset: 0;
  border-radius: inherit;
  background: linear-gradient(105deg, transparent 30%, rgba(255,255,255,.55) 50%, transparent 70%);
  background-size: 220% 100%;
  animation: sheen 260ms var(--ease-out) 1;
  pointer-events: none;
}
@keyframes sheen { from { background-position: 130% 0 } to { background-position: -30% 0 } }
```

**深色模式**：玻璃底改为 `rgba(28,30,38,.72)`，内高光降到 `.12`，
`--island-border` 走白 8%。

**降级**（三道，缺一不可）：

1. 不支持 `backdrop-filter` → 实心 `--surface` + 常规阴影（@supports 探测）
2. `prefers-reduced-transparency` → 同上
3. `prefers-reduced-motion` → 保留形变，取消 `sheen` 与上移 FLIP，
   改为即时的 `opacity` 过渡

**性能红线**：

- 只动画 `transform` / `opacity` / `filter`，**绝不动画 `backdrop-filter`**（会触发重绘）
- 岛内元素加 `will-change: transform`，动画结束后移除
- 岛栈同屏上限 5 个，超出的先折叠汇总

## 3. 全局适配：让岛看起来「本该在这里」

这是你提的关键问题。逐条处理：

### 3.1 空间留白（最重要）

岛只在**工具活跃时**出现，所以留白要按「两种情况都不难看」来设计：

- 空闲态：消息列 `max-width: 700px` **几何居中**，与无岛时完全一致。
  不做任何为岛预留的永久空白 —— 预留出来的空位就是 §1.1 说的「空地」。
- 活跃态：岛落在消息列右侧的**既有**留白里（`1400px` 窗口下右侧本身就有约 250px），
  消息列不动。
- 窗口窄于 `1180px`、右侧留白不足时，消息列才用 `transform` 左移让位（240ms），
  而不是改 `margin` 触发重排。
- 岛与消息列之间**不加垂直基线**：岛是临时出现的，为它画一条长期存在的轨道线，
  反而会在空闲时留下一道没有用途的竖线。轨道感由岛自身的位移动画提供，
  不需要静态装饰来暗示。
- Composer 宽度不随岛变化，避免输入框在工具调用时忽宽忽窄。

### 3.2 材料呼应

不要让玻璃孤立：

- Composer 聚焦时，边框高光用**同一套品牌渐变描边**（但仍是实心底，不用玻璃）
- Toast、右键菜单、命令面板**统一升级到 L2 玻璃**，与岛同一材质
- 任务卡保持 L1 实心 —— 它是「已落定的结果」，不再需要悬浮感

### 3.3 动效节奏统一

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| hover / 颜色 | 120ms | `--ease-out` |
| 状态切换（岛内） | 180ms | `--ease-out` |
| **岛展开 / 收缩** | 220ms | `--ease-island: cubic-bezier(.32,.72,0,1)` |
| **岛上移 FLIP** | 320ms | `--ease-island` |
| 面板 / 岛降级切换 | 240ms | `--ease-island` |
| 消息淡入 | 120ms | `--ease-out` |

`--ease-island` 是一条轻微过冲的曲线（`.32,.72,0,1` 的近似物），
是全应用**唯一**允许有「惯性感」的曲线，只在岛和面板上使用。其余一律 `--ease-out`。

### 3.4 需要一起改掉的旧装饰

上一版已识别，这里补上「为什么它和岛冲突」：

| 旧元素 | 冲突点 |
| --- | --- |
| 欢迎页 32px 渐变标题 + 鼠标跟随光斑 | 与岛争抢「唯一亮点」，且光斑是伪液态，材质语义混淆 |
| `.cursor` 无限发光 | 岛已有脉冲，两处发光会互相削弱 |
| `.welcome-action:hover` 抬升 + 图标旋转 | 抬升语义与岛的上移语义冲突，用户会误读 |
| `model-tool-card` 渐变底 | 它就是岛要取代的东西，必须删 |
| 头像 / 发送键的 `brand-grad` | 把品牌渐变留给描边和岛高光，实心元素改纯色 |

原则：**造物性动效归岛，其余一切归静**。

### 4.5 Token 用量

现状问题：`usage` 只算**当前会话**（`main.tsx:298`），切会话就归零，
且会话内 JSONL 全量读取，无法跨会话统计。

分层方案：

| 层级 | 位置 | 内容 |
| --- | --- | --- |
| 会话级 | 岛栈底部固定行 | `本轮 2.4k · 会话 42.1k` |
| 项目级 | 项目视图概览卡 | 该项目全部会话累计 |
| 全局级 | 设置 › 用量 | 按天 / 按模型 / 按工具 |

实现：客户端按 `sessionId` 缓存每条 assistant 事件的 `usage`，
用 `localStorage` 持久化聚合值（键为 `usage:v1:<sessionId>`），
启动时先读缓存再后台校准。**不需要改宿主**。

全局视图：

```

09-28    412k      98k       510k     ████████
09-27    388k      102k      490k     ███████
09-26    401k      180k      581k     █████████
```

条形用单色品牌色，不用彩虹渐变；数字 16px `tabular-nums`，
**不做 28px 巨型数字**。

## 5. 交互规则

1. **点击即响应**：会话/项目/工具选择在点击帧更新选中态，请求后台补数据
2. **乐观插入**：用户消息先入本地 timeline（`pending` 态），`chat.send` 返回后替换
3. **轮询按需**：仅 `streaming || 有 running 任务` 时 1s 轮询；空闲降到 5s 且内容 diff 后才 `setState`
4. **岛不夺焦**：岛的任何状态变化都不移动焦点、不滚动消息区
5. **会话切换保留岛态**：岛的动画状态提升到 App 并按 `sessionId` 缓存，
   切回来不重播动画
6. **Esc 分级**：关抽屉 → 关玻璃浮层 → 关模态框 → 不动其他
7. **键盘全可达**：岛可 Tab 聚焦，`Enter` 展开详情，`⌘.` 中断当前调用
