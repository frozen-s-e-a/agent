# AI 审计助手客户端
# 九类审计任务工作流详细设计方案

版本：v1.0（设计稿）

日期：2026-09-30
适用范围：Windows Electron + React 客户端

---

## 1. 设计目标

AI 审计助手不应以“聊天窗口”为产品骨架。现有程序已经具备表格处理、账簿核查、月间分析、银行流水、明细表、披露附注、关联方查询等真实业务能力，客户端需要把这些能力组织成用户能理解、能复核、能恢复的任务流程。

本方案的目标是：

1. 用户先选择真实的审计任务，再进入任务专属流程。
2. 每个任务阶段都有明确输入、系统动作、人工确认点和阶段性成果。
3. 参数、确认和追问都在当前阶段完成，不把任务拆回聊天窗口。
4. 每个结果都能回到规则、字段、输入文件和原始位置。
5. 长任务支持进度、取消、重试、恢复和阶段检查点。
6. 设计不改变现有业务规则、阈值、抽样方法和模板语义。

## 2. 能力基线

## 3. 产品信息架构

### 3.1 一级导航

左侧导航采用新的任务工作台结构，不沿用旧客户端的项目树、工具列表或聊天优先布局：

- **任务中心**：按九类真实审计任务进入新任务。
- **处理记录**：按当前项目查看可继续的工作和历史状态。
- **设置**：配置模型和运行环境，不参与任务主路径。

项目切换放在顶部任务上下文；文件只在当前阶段按需选择，不能用一个常驻文件栏代替任务范围。

### 3.2 任务中心

首页标题使用“从任务开始，而不是从工具开始”，展示九类任务卡。每张卡显示：

- 任务名称和一句业务目的说明。
- 适用输入，例如“序时账 + 银行流水”。
- 预计步骤数量。
- 典型阶段成果，例如“匹配率、差异清单、函证数据”。
- 最近一次使用时间和任务状态。

工具能力只通过任务阶段提供。没有对应已注册执行能力的阶段必须显示不可执行状态，不能把缺少实现的工具伪装成已完成。

### 3.3 共用任务壳

进入任一任务后，使用统一的三段结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 任务名称  项目  输入快照  当前状态        本地运行 / 活动记录 │
├──────────────┬─────────────────────────────┬─────────────────┤
│ 专属阶段导航 │ 当前阶段工作区              │ 阶段产物/检查器  │
│              │ 输入、参数、结果、下一步      │ 按需展开          │
└──────────────┴─────────────────────────────┴─────────────────┘
```

- 左侧宽度约 210px，显示当前任务专属阶段，不显示通用文件树。
- 中间是当前阶段主工作区，宽度优先保证表格和结果阅读。
- 右侧固定显示阶段产物摘要；只有生成结果后才展开行数、警告、输出文件和复核证据。
- 阶段内不嵌入旧版聊天栏；需要说明时使用阶段说明、参数提示和成果原文完成复核。

## 4. 共用任务生命周期

所有任务都使用同一套顶层状态，但阶段名称和产物不同：

1. `draft`：任务已创建，尚未确认输入。
2. `preparing`：系统正在预览文件、识别结构或加载模板。
3. `awaiting_confirmation`：系统已给出映射、规则或计划，需要用户确认。
4. `running`：工具链正在执行。
5. `review_required`：已生成结果，需要用户复核异常、差异或配置。
6. `completed`：任务结果和输出包已生成。
7. `failed`：失败，显示具体步骤和可执行修复。
8. `interrupted`：用户取消或应用退出，显示最近检查点。
9. `recovery_required`：恢复前需要确认输入快照、规则版本或已提交批次。

每个状态都必须有可见的下一步动作。不能只显示“处理中”或“完成”。

## 5. T01 表格与资料整理

### 5.1 适用任务

文件结构查看、表头处理、多文件合并、列提取、字段清理、删除合计行、文本匹配、资料清单和 PDF 文本提取。

### 5.2 任务步骤

1. **选择资料**：文件或文件夹，显示类型、数量和授权范围。
2. **检查结构**：工作表、表头位置、列名、行数和样例。
3. **定义整理动作**：合并、选择列、填充、删除合计行、文本筛选等。
4. **预览变更**：展示变更前后行数、列数和样例差异。
5. **生成副本**：输出新文件，原件保持不变。

### 5.3 阶段成果

- 输入资料清单。
- 工作表结构摘要。
- 整理规则和参数。
- 变更统计：新增列、删除行、合并文件数。
- 输出文件和原始文件对应关系。

### 5.4 关键交互

整理动作以“步骤列表”呈现，允许拖动调整顺序。每一步提供撤销和预览，不使用模糊的“运行全部”。

---

## 6. T02 科目、账簿与凭证

### 6.1 适用任务

科目字段清理、辅助项处理、凭证借贷核对、JET 会计分录测试、小账套校验和科目余额表处理。

### 6.2 凭证核对流程

1. 读取序时账并检查日期、凭证号、借方、贷方字段。
2. 选择分组键和允许差额。
3. 按凭证键汇总借贷金额。
4. 展示不平凭证、差额和原始分录定位。
5. 导出疑点清单或进入人工复核。

### 6.3 JET 分录测试流程

1. `jet_test_inspect` 检查数据源结构。
2. 选择内置规则或自定义规则。
3. 展示规则需要的源列和样例。
4. `jet_test_execute` 执行测试。
5. 按规则、风险和凭证定位疑点。

### 6.4 阶段成果

- 字段和类型检查报告。
- 规则清单与规则版本。
- 规则命中统计。
- 疑点凭证表。
- 原始文件、工作表、行号和凭证号定位。

## 7. T03 月间分析与测算

### 7.1 实际工具链

`monthly_preview` → `monthly_detect_structure` → `monthly_execute` → `monthly_ai_analysis`（可选）。

### 7.2 任务步骤

1. **数据预览**：文件、列名、类型、样例和基础统计。
2. **科目结构识别**：分隔符、层级、步长和编码范围。
3. **字段与科目确认**：日期、科目、借方、贷方和分析科目。
4. **执行月间汇总**：按月份和科目生成结果表。
5. **查看变动排行**：按绝对值、比例和缺失期间筛选。
6. **原因分析**：只对用户确认的超阈值科目运行 AI 分析。

### 7.3 阶段成果

- 数据源概览。
- 科目层级识别报告。
- 字段映射和分析科目清单。
- 月度汇总表。
- 超阈值变动清单。
- AI 原因分析草稿，明确标注为解释建议而非审计结论。

### 7.4 关键交互

每一步完成后暂停并等待确认，不能连续自动调用多个工具。结果页面提供“返回修改”和“确认进入下一步”。

## 8. T04 抽凭与抽样

### 8.1 任务步骤

1. 定义总体：数据源、期间、总体金额和剔除条件。
2. 选择抽样方法：随机、金额加权、截止测试或指定规则。
3. 设置样本量、种子、金额阈值和截止日期。
4. 生成样本并显示覆盖率。
5. 记录抽查结果、补充样本和复核意见。
6. 导出抽样底稿和样本清单。

### 8.2 阶段成果

- 总体定义快照。
- 抽样方法和参数。
- 随机种子或可复现依据。
- 样本清单和金额覆盖率。
- 补抽记录。
- 抽查结论和未完成样本。

### 8.3 关键交互

抽样方法、总体和样本量确认后才允许生成样本。重新抽样必须生成新版本，不能覆盖原样本。

## 9. T05 银行业务

### 9.1 实际任务链

`bankflowmerge` → 字段和账户确认 → `bank_flow` → 未匹配/差异复核 → `bank_digit2` 或 `bank_paper1`/`bank_paper2`。

### 9.2 任务步骤

1. 选择银行流水和序时账。
2. 合并多银行、多账户流水，保留来源文件和账户信息。
3. 确认日期、收入、支出、对手方、凭证号和银行科目字段。
4. 执行双向核对。
5. 查看匹配率、未匹配、金额差异和文本相似度结果。
6. 选择函证格式并生成输出。

### 9.3 阶段成果

- 合并流水预览。
- 账户和字段映射。
- 匹配率和匹配规则摘要。
- 未匹配交易清单。
- 金额差异清单。
- 函证数据或函证表格。

### 9.4 证据展示

每笔差异提供银行流水行、序时账行、匹配依据、金额差额和对手方文本。用户可以标记“已解释、需补证、误匹配”。

## 10. T06 底稿、明细表与结转

### 10.1 实际工具链

`detailed_table_inspect` → `detailed_table_inspect_template` → `detailed_table_save_config` → `detailed_table_validate` → `detailed_table_generate`。

### 10.2 任务步骤

1. 检查数据源文件、公司、科目和字段。
2. 检查底稿模板的工作表和批注字段。
3. 确认字段映射、科目映射和模板分配。
4. 保存配置，显示配置版本。
5. 校验配置完整性和一致性。
6. 批量生成明细表或底稿。
7. 检查公式、链接、输出文件和失败公司。

### 10.3 阶段成果

- 数据源检查报告。
- 模板结构清单。
- 映射差异和未匹配字段。
- 配置文件版本。
- 配置校验报告。
- 生成文件清单和失败清单。

### 10.4 关键交互

配置确认前不能生成文件。生成阶段按公司/文件显示进度，失败项可以单独重试，不重做已成功文件。

## 11. T07 披露、附注与链接

### 11.1 任务步骤

1. 选择合并报表、附注和底稿文件。
2. 提取披露范围和披露表。
3. 检查附注模板与底稿字段的对应关系。
4. 执行附注穿透、填充或批注插入。
5. 执行链接提取或链接替换。
6. 检查输出文件中的引用和路径。

### 11.2 阶段成果

- 披露范围清单。
- 披露表预览。
- 公司/科目/工作表映射。
- 批注和链接变更清单。
- 输出引用检查报告。

### 11.3 安全要求

默认生成副本，不直接覆盖原文件。涉及链接替换、批注插入和模板写入时，必须在执行前展示影响文件清单。

## 12. T08 关联方与外部查询

### 12.1 任务步骤

1. 选择被审计单位、客户、供应商和高管名单。
2. 通过 `cicpa_query` 查询或导出工商信息。
3. 通过 `related_party` 执行多维度匹配和检测。
4. 处理企查查报告、地址和公司名称差异。
5. 展示疑似关联方、匹配依据和缺少证据。
6. 导出关联方核查结果和来源资料。

### 12.2 阶段成果

- 查询主体清单。
- 工商信息来源和时间。
- 名称、股权、地址、人员等匹配维度。
- 疑似关联方清单。
- 匹配证据和人工确认状态。
- 外部查询下载文件清单。

### 12.3 外部访问提示

外部查询必须明确显示网络访问、数据来源和查询时间。没有有效授权或连接时，不能显示为“已完成”。

## 13. T09 信息提取与辅助处理

### 13.1 任务类型

- PDF 和多类型文件关键信息提取。
- 身份证信息解析。
- 地址拆分和函证地址核查。
- 纸质信息核对。
- 图片智能重命名。

### 13.2 共用流程

1. 识别输入类型和所需输出。
2. 预览可识别内容和缺失项。
3. 选择提取字段或处理规则。
4. 执行转换/提取。
5. 人工复核低置信度结果。
6. 生成结构化表格、重命名文件或辅助输出。

### 13.3 阶段成果

- 输入文件和页码/图片清单。
- 提取字段和置信度。
- 低置信度待复核项。
- 结构化结果预览。
- 输出文件和处理日志。

## 14. 阶段成果与证据链

所有任务结果都使用统一的 Result 结构：

```text
Result
├── taskId
├── taskType
├── inputSnapshot
├── toolChain
├── parameters
├── ruleVersion
├── summaryMetrics
├── artifacts[]
├── findings[]
├── evidenceRefs[]
├── warnings[]
└── reviewStatus
```

### 14.1 结果摘要卡

每张结果卡必须回答：

- 处理了多少文件、工作表、行或记录。
- 找到了多少异常、差异、样本或输出文件。
- 有多少项目需要人工确认。
- 下一步可以做什么。

### 14.2 证据引用

证据引用至少包含：

- 文件路径或任务内文件 ID。
- 文件指纹或输入快照版本。
- 工作表、单元格、行号或 PDF 页码。
- 产生证据的工具和规则版本。
- 复核状态、备注和时间。

### 14.3 结果状态

结果状态不能只依靠颜色，必须同时显示文字和图标：

- 可使用
- 需要确认
- 已确认
- 误报
- 缺少资料
- 执行失败
- 可恢复
- 已导出

## 15. 共用组件

### 15.1 任务入口组件

- `TaskTypeCard`：任务名称、输入、步骤、产物。
- `RecentTaskList`：任务类型、项目、状态、更新时间。
- `TaskSearch`：按任务名称、业务目的和成果搜索。

### 15.2 阶段组件

- `TaskStageRail`：专属阶段、当前状态、完成产物数量。
- `StageHeader`：阶段目标、输入快照、当前状态。
- `InputScopeCard`：文件、文件夹、授权和快照。
- `FieldMappingTable`：目标字段、来源列、置信度、人工确认。
- `RuleCard`：规则名称、版本、参数和影响范围。
- `ExecutionTimeline`：步骤、进度、耗时、警告、取消、恢复。
- `ResultSummary`：真实业务数字和下一步动作。
- `EvidenceInspector`：文件定位、规则来源、原始位置、备注。
- `OutputPackage`：输出文件、版本、生成时间和打开目录。

### 15.3 成果与复核组件

阶段成果面板承担可复核信息的集中展示：

- 展示真实任务状态、处理行数、警告和输出文件。
- 展示 Legacy MCP 返回的原文内容，避免把执行结果藏在旧消息卡片中。
- 对失败阶段提供重试入口，并保留本阶段的输入和执行能力选择。
- 通过 RESULT CONTRACT 提醒用户本阶段应该产出的成果。

## 16. 交互与状态设计

### 16.1 阶段进度

使用步骤条表达阶段关系，但真实状态立即更新。进入下一步前必须满足前置条件；动画不能延迟导航或伪造完成。

### 16.2 长任务

长任务必须显示：

- 当前工具和阶段。
- 已处理文件/行/记录数。
- 已完成批次和剩余批次。
- 警告、失败和跳过数量。
- 最近检查点。
- 取消、重试和恢复入口。

### 16.3 错误

错误信息按“发生了什么 → 影响什么 → 下一步怎么处理”书写。例如：

> 往来款明细.xlsx 的“明细”工作表有 18 行无法识别对手方字段。可以替换文件、排除该文件，或继续并在字段映射阶段人工处理。

### 16.4 版本

以下变更生成新版本，不覆盖旧记录：

- 输入文件替换或范围扩大。
- 字段映射修改。
- 规则或参数修改。
- 重新抽样。
- 重新生成底稿。

### 16.5 无障碍与动效

- 所有阶段、按钮和图标支持键盘操作。
- 选中、错误和待确认状态不能只通过颜色表达。
- `prefers-reduced-motion` 下保留状态变化和焦点，不使用位移动画。
- 展开证据详情时保持焦点和阅读顺序。

---

## 17. 数据安全和原件保护

- 默认只读取项目授权范围内的文件。
- 所有生成、清洗和替换操作默认写入副本。
- 覆盖、删除、范围扩大和外部查询必须明确确认。
- 输入快照保存文件指纹，结果引用快照版本。
- 外部查询显示来源、时间和网络访问状态。
- 外部 MCP 不因“已安装”自动获得项目文件权限。

## 18. 落地优先级

### P0：共用任务壳

- 任务中心。
- 任务记录。
- 任务专属阶段导航。
- 输入快照、执行时间线、结果摘要、证据检查器。

### P1：优先实现三条代表性任务链

1. 月间分析：已有 Skill 和多步 MCP 流程，最适合验证阶段确认模型。
2. 明细表生成：已有检查、配置、校验和生成链，最适合验证阶段产物模型。
3. 银行流水核对：最适合验证多文件、匹配差异和证据复核界面。

### P2：扩展任务链

- JET 分录测试。
- 表格资料整理。
- 披露与附注链接。
- 抽凭与抽样。

### P3：外部和辅助能力

- 关联方与外部查询。
- PDF/图片/身份证/地址等辅助处理。
- 工具搜索、Skill 管理和高级 MCP 设置。

## 19. 验收标准

### 任务发现

- 新用户能在 30 秒内找到目标任务类型。
- 任务卡说明输入、步骤和输出，不要求用户先理解工具 ID。

### 阶段可理解性

- 每个阶段都有清晰的目标、输入、结果和下一步。
- 不同任务使用不同的阶段名称和结果指标。

### 可复核性

- 任意异常都能定位到规则、字段、输入文件和原始位置。
- 任意输出都能反向查看使用的输入快照和参数。

### 可恢复性

- 长任务取消后能显示最近检查点。
- 重试只重做失败或未提交步骤。
- 文件和规则变更会生成新版本，不覆盖旧结果。

### 业务正确性

- 不改变原工具的公式、阈值、抽样方式、模板和输出要求。
- 低置信度映射、外部查询缺失和配置校验失败必须阻止静默继续。

---

## 20. 明确不做的事情

- 不把九类任务压成一套完全相同的表单。
- 不把所有 MCP 工具直接平铺在首页。
- 不让模型自动决定重大性、抽样方法、规则阈值或最终审计结论。
- 不以漂亮的进度动画代替真实执行状态。
- 不把“已注册工具”宣传成“全部功能都已行为验收”。
