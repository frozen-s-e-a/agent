# 审计助手客户端界面优化方案（已归档）

> 本文属于旧版客户端的历史评审，不再作为实现依据。当前实现规范见 `docs/spec.md`，九类任务流程见 `docs/AI审计助手_九类任务工作流详细设计方案.md`。

> 本文是对现有客户端（`src/client/`）的设计评审与重构方案，优先级顺序即实施顺序。
> 约束：不改动业务逻辑、API 协议与 Electron 宿主代码，只调整信息组织、状态呈现与视觉规范。

## 0. 评审结论

现有实现的功能完整度没有问题，主要问题集中在三类：

1. **布局与运行时缺陷**（A 级，影响可用性）：消息区滚动链路失效、空闲时每秒全树重渲染、右侧面板每次打开重放入场动画。
2. **信息冗余**（B 级，影响认知）：同一信息（工作范围、本地状态、文件选择）在 2–4 处重复出现；工具执行要跨 2 个模态框。
3. **视觉规范漂移**（B 级，影响质感）：7 种不同的容器语言、大量装饰性动效，与 `DESIGN.md` 和需求书第 7/10 条直接冲突。

## 1. 当前 UX 问题

### A 级（影响效率，必修）

**A1 · 滚动容器层级 bug —— 主内容区实际不可滚动**

`main.tsx:377` 的 `.workspace` 是 `flex-direction: column`，而 `.conversation` 设了 `flex: 1`，
在 column 父容器里等于「高度撑满」而非「占剩余空间」，`flex: 1` 对其失效。消息列表靠外层
`overflow: hidden` 撑着，消息一长滚动行为即异常，Composer 有被挤出视口的风险。
`.chat-column` 在同一容器里重复了一遍 `flex: 1`，两套规则互相抵消。

**A2 · 整棵应用每秒重渲染**

`main.tsx:111` 用 `setInterval(tick, 1000)` 无条件写 `timeline`，即便流式已结束、内容零变化。
`timeline` 是根部 state，于是 Sidebar、ContextPanel、Composer、Messages 全部每秒重算，
`refresh()` 也每秒重跑一次 `bootstrap`。长时间驻留会带来可完全避免的 CPU 与风扇开销。

**A3 · 右侧面板每次打开都重放动画**

`style.css:437` 的 `drawer-in 220ms` 挂在条件渲染的 `.context-panel` 上，每次切换都重新入场一次。
违反需求书第 6 条「切换页面保持布局稳定，不出现闪烁」。且只有入场没有真正的收起动画——是硬闪。

**A4 · 三个工具入口，三种形态**

`Ctrl+K` 搜索框、欢迎页「浏览工具」、输入框工具栏「工具」指向同一个模态框；
选中工具后又跳到 780px 的参数模态框，框内还有一整套文件选择器，与右侧面板功能完全重叠。
执行一次工具平均跨越 2 个模态框 + 1 个面板。

**A5 · 启动即创建空对话**

`main.tsx:90-95` 在无会话时自动 `session.create`。用户只想打开应用看历史，就已经被塞了
一个「新对话」进侧栏，会话列表越积越多。

### B 级（信息冗余与视觉噪音）

**B1 · 同一份信息在多处重复**

| 信息 | 出现位置 |
| --- | --- |
| 工作范围 | 顶部栏 pill、欢迎页 work-scope、右侧面板 project-scope |
| 本地状态 | 顶部栏 local-pill、面板 scope-note、面板 context-footer、侧栏「本地运行」 |
| 文件选择 | 右侧面板整套 + 参数模态框内整套 |

**B2 · 顶部栏只做装饰**
52–58px 高，唯一有用信息是右侧面板开关。

**B3 · 视觉层级用错了手段**
需求书第 4 条要求「不要通过大量边框划分区域」，实现恰好相反：
`.message.assistant .message-content`、`.task-card`、`.model-tool-card`、`.settings-card`、
`.project-scope`、`.file-breadcrumb`、`.scope-note`、`.info-box` 全部是
「边框 + 浅底 + 圆角」的同一种容器，**7 种卡片语言出现在同一屏**，且存在 Card 套 Card
（`settings-card > info-box`、`task-card > data-table`）。

**B4 · 装饰性动效与需求书第 7/10 条直接冲突**

- `.welcome-action:hover` → `translateY(-3px)` + 图标 `scale(1.04) rotate(-2deg)` + 鼠标跟随光斑
  （`WelcomePage.tsx:20` 每次 mousemove 还写 DOM 自定义属性）
- `.welcome-title` 渐变文字 + 下划线 `width-open` 动画
- `.cursor` 的 `glow-cursor` 无限发光
- `.no-project > div` 的 `breathe` 无限缩放
- `.nav-item:hover` → `translateX(2px)`
- `.composer:focus-within` → `translateY(-1px)` + 最重的 `--shadow-lg`

**B5 · 需求书第 10 条禁止项命中清单**

大量渐变（`brand-grad` 用于头像/发送键/主按钮/图标底/标题文字）、发光（cursor、
welcome-icon shadow、status-dot 的 3px ring）、巨大数字（`.stat strong` 28px、
`.result-summary b` 22px）、过大标题（`.welcome-title` 32px，并靠 `max-height` 断点缩到 22px）、
大量阴影（4 级 shadow + 各处硬编码 `0 6px 20px #5b5bd640`）。

**B6 · 状态矩阵大面积缺失**

需求书第 8 条要求十态，实测缺口：

- body 无 `:active`，只有 `scale(.97)`，看不出按下
- 列表项无 `:focus-visible`（仅 `.session-row:focus-within` 显示删除键），键盘用户失去焦点位置
- 空状态只有 3 处（无项目、文件夹为空、无结果文件）；搜索无结果、项目无对话、
  用量为空、模型列表为空均缺失
- 加载态用文本代替（`phase || '正在连接模型…'`），无骨架屏
- `prefers-reduced-motion` 兜底错误：`animation-duration: 1ms !important` +
  `iteration-count: 1` 会让 `glow-cursor`、`indeterminate` 冻结在起点，进度条看起来像卡死

**B7 · 键盘与实现细节**

`button { display: inline-flex }` 是全局的，靠 `.nav-item > span:not([class])`
挑出需要 ellipsis 的文本——用「无 class」当选择器条件，极其脆弱。
侧栏删除按钮用 React `hoveredSession` state 控制显隐（`Sidebar.tsx:103`），
每次 hover 触发父组件重渲染，而 CSS 里已有 `.session-row:hover .session-delete` —— 两套机制并存。

## 2. 新的信息架构

核心原则：**每条信息只有一个「家」。**

```
项目（工作边界）
└── 对话（执行单元）
    ├── 消息流（自然语言 + 流式输出）
    ├── 工具调用（内联，折叠）
    └── 任务卡（结果 + 输出文件 + 校验）
```

职责重新划分：

| 信息 | 唯一归属 | 从别处删除 |
| --- | --- | --- |
| 当前项目 / 工作范围 | 右侧面板顶部「项目范围」 | 顶部栏 pill、欢迎页 work-scope |
| 文件浏览与选择 | 右侧面板（唯一入口） | 参数模态框内的文件选择器 |
| 本地执行状态 | 侧栏底部一处 | 顶部栏 local-pill、面板 context-footer、scope-note 重复段 |
| 工具入口 | 输入框 `/` + 工具栏「工具」 | 欢迎页「浏览工具」按钮 |
| 结果文件 | 任务卡内 | — |
| 设置 | 独立页面 | — |

工具执行路径从「搜索框 → 参数模态框」改为**右侧面板原位切换**：

```
点击工具 → 右面板从「文件」滑入「工具配置」
         → 配置完成 → 右面板回到「文件」，任务卡出现在消息流
```

屏幕中央的消息流永不被遮挡，符合需求书第 9 条「后台 Agent 不阻塞用户操作」。

## 3. 页面布局方案

```
┌────────────┬──────────────────────────────────────┬─────────────┐
│ Sidebar    │ Topbar  52px                          │ 面板 300px   │
│ 248px      │  面包屑（项目 / 对话）      [面板开关] │             │
│ 可折叠     ├──────────────────────────────────────┤ 项目范围     │
│            │                                      │ ─────────── │
│ 新建对话    │   消息流（最大 720px，居中）           │ 文件浏览器   │
│ 搜索        │                                      │ ─────────── │
│ ─────────  │   ── Composer（最大 720px）──         │ 已选文件     │
│ 项目列表    │                                      │ ─────────── │
│ 独立对话    │                                      │ 本地状态     │
│ ─────────  │                                      │             │
│ ● 本地      │                                      │             │
│ 设置        │                                      │             │
└────────────┴──────────────────────────────────────┴─────────────┘
```

规格说明：

- **Sidebar**：`248px`，可折叠至 `0`（`width` 过渡，`--ease-drawer`，240ms）。
  分区只保留「项目」和「独立对话」两组，去掉 `max-height: 30vh` 硬限制，
  改为整组占满剩余高度。搜索入口移到顶栏与输入框。
- **Topbar**：`52px`，只放面包屑（`项目 › 对话`，单行 ellipsis）与右侧两个按钮
  （面板开关、折叠侧栏）。去掉边框与 `backdrop-filter`，改用 `--bg` 与 `--surface`
  的明度差自然分区。
- **消息流**：`max-width: 720px`（当前 860px 偏宽，长段落行长达 90+ 字符），
  左右 `padding: 32px`。
- **右侧面板**：`300px`，开合状态提升到 `App`，用 `width` + `transform` 过渡而非条件渲染。
  内部三个可折叠区段，用留白分隔，不用边框。
- **欢迎页**：从「32px 大标题 + 三张卡」改为紧凑排列——一行 `18px` 标题 + 一行说明 +
  三行快捷入口（左图标右文字，`48px` 行高），信息密度提升，首屏不再需要
  `max-height` 断点降级。

## 4. 组件设计规则

### 4.1 按钮（三级，其余归菜单）

| 级别 | 用途 | 规格 |
| --- | --- | --- |
| Primary | 每屏最多 1 个（发送、确认并执行、保存） | 品牌色实底，`32px` 高，`radius 6px`，无阴影 |
| Secondary | 次操作（取消、刷新） | 无边框无底色，hover 显 `--surface-3` |
| Ghost / Icon | 低频操作 | 仅显图标，hover 显底，`28×28` |

删除 `.welcome-tools button`、`.output-files button`、`.nav-search` 这类「带边框小按钮」，
统一为 Secondary 的 text button 样式。

### 4.2 输入框

- 默认：无边框，仅 `1px` 的 `--line` 底边
- Focus：底边变 `--brand` + `0 0 0 3px var(--brand-ink-2)`，**不移位、不加阴影、不改圆角**
- Composer：保留「包裹容器带边框」方案，但 focus 时只改边框色，
  删除 `translateY(-1px)` 与 `--shadow-lg`

### 4.3 列表行（统一组件 `Row`）

- 高度 `32px`，水平 padding `8px`，圆角 `6px`
- hover：`background: --surface-3`，**无位移**
- selected：`background: --brand-ink` + `color: --brand`，左侧 `2px` 品牌色指示条
- 键盘 focus：`outline: 2px solid --brand-line; outline-offset: -2px`（贴边内描边，不撑开布局）

### 4.4 容器语言统一为 2 种（当前 7 种）

1. `surface`：纯白 + `1px --line` + `radius 10px` —— 用于消息、任务卡、设置卡
2. `inset`：`--surface-2` + 无边框 —— 用于嵌入块（代码、表格、日志）

删除所有渐变容器与所有 hover 抬升阴影。

### 4.5 状态矩阵

`Row` / `Button` / `Input` 三类共用一套变量：

```
default   → 基础样式
hover     → 背景一档（--surface-3）
active    → 背景二档（--line），无缩放
selected  → 品牌浅底 + 左侧指示条
focus     → 2px 内描边
loading   → 保留原文字宽度，右侧 12px 旋转图标（不替换内容，避免布局跳动）
disabled  → opacity .4，cursor not-allowed
error     → 文本 --danger，底 --danger-bg
success   → 文本 --success，底 --success-bg
empty     → 居中：标题 13px --ink-2 + 说明 11px --ink-3 + 一个操作
```

## 5. 交互规则

1. **点击立即响应**：会话切换、面板切换、工具选择在点击帧内更新 `selected`，
   网络请求后台完成。`selectProject` 当前先 `await` 再切换，需改为先切换再补数据。
2. **发送消息乐观插入**：用户消息先进本地 `timeline` 并标记 `pending`，
   `chat.send` 返回后替换为真实事件。当前是等 API 返回才显示。
3. **轮询按需运行**：仅当 `timeline.streaming || 有 running 任务` 时按 1s 轮询，
   其余状态停止或降频到 5s；内容无变化不 `setState`。
4. **工具不再跳模态框**：右面板原位切换视图，中央消息流保留滚动位置。
5. **新建对话不自动落盘**：侧栏「新建对话」只切换到空态视图，首次发送时才真正创建。
6. **跨会话通知**：后台任务完成时若用户已切到别的会话，用侧栏会话行角标提示，
   不夺取当前视图。
7. **Esc 分级**：先关面板内层视图 → 再关模态框 → 不动其他。
   当前 `Escape` 无条件清 `modalType`/`currentTool`/`deleteConfirm`。
8. **键盘可达**：侧栏、列表、任务卡操作全部可 Tab 到达；删除键显隐纯用 CSS
   （`:hover` / `:focus-within`），移除 React 的 `hoveredSession` state。

## 6. 动画规则

| 场景 | 目标 | 当前 |
| --- | --- | --- |
| hover 背景/颜色 | 120ms | 140ms（可接受） |
| 状态切换 | 160ms | 200ms |
| 面板开合 | 200ms | 220ms 但无真正开合，只有入场 |
| 模态框 | 160ms `fade` + `scale(.98)` | 220ms `scale(.96)`（略大） |

**曲线统一为两条**：`--ease-out: cubic-bezier(0.23,1,0.32,1)` 用于所有状态切换；
`--ease-drawer: cubic-bezier(0.32,0.72,0,1)` 只用于面板宽度。删除 `--ease-in-out`。

### 删除清单（与需求书第 7、10 条冲突）

- `slide-in-left` / `slide-in-right`（消息滑动入场）→ 改为只淡入，120ms
- `shake-in`（错误消息抖动）
- `breathe`（无限缩放）
- `glow-cursor`（发光光标）→ 静态 `2px` 品牌色方块，闪烁用 `opacity`
- `width-open`（欢迎页标题下划线展开）
- `welcome-title` 渐变文字 + 下划线
- `welcome-action` 鼠标跟随光斑 + `rotate(-2deg)` + `translateY(-3px)`
- 所有 `:hover { transform: translateX/Y }`（`.nav-item`、`.welcome-action`、
  `.settings-tabs button`、`.search-results button`、`.task-card`、`.mode-cards button`）
- `.composer:focus-within { transform: translateY(-1px) }`

### 保留

`rise`（页面首次进入，6px，200ms）、`pop`（模态框）、`drawer-in`（改为真正的宽度过渡）、
`indeterminate`（进度条，状态传达而非装饰）、`spin`、`announce`（通知）。

### `prefers-reduced-motion` 修正

不能对 `indeterminate`、`spin` 用 `1ms + iteration-count: 1`，会让它们冻结在无效状态：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: 1ms !important;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
  }
  /* 状态指示类动画必须继续运行，否则看起来像卡死 */
  .indeterminate { animation-duration: 2s !important; animation-iteration-count: infinite !important; }
  .spin { animation-duration: 1.1s !important; animation-iteration-count: infinite !important; }
  .cursor { animation-duration: 1.2s !important; animation-iteration-count: infinite !important; }
}
```

## 8. 验收标准

- 同一信息在全应用只出现一次
- 工具执行全程中央区不被遮挡
