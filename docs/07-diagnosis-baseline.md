# 07 问题诊断与评估基准（阶段 0）

**目的**：改造前先确认问题出在哪里。配置问题和模型能力问题的症状相同（想不深、做不完、慢、有瑕疵），但处理方式和成本差别很大。配置问题修复快、见效快；模型能力问题才需要 03、05、06、08 中的结构化改造。

---

## 一、诊断清单

| # | 检查项 | 怎么检查 | 判断标准 | 有问题怎么处理 |
|---|---|---|---|---|
| 1 | 实际上下文长度 | 查推理服务启动参数（vLLM `--max-model-len`、SGLang `--context-length`、Ollama `num_ctx`、llama.cpp `-c`）和客户端的最大上下文配置；发送已知长度的请求，看是否报错或被截断 | 生效值明显小于模型标称值 | 调大参数（注意显存与并发的取舍） |
| 2 | 提示词占用 | 抓取一次真实请求的完整 messages，用模型自身的分词器分别统计 system prompt、引导文件、工具描述、历史的 token 数 | 任务开始前固定部分超过有效上下文的 30% 视为过重 | 裁剪章节，按场景加载 |
| 3 | 思考参数是否生效 | 同一组问题分别用思考 off 和 high 运行，比较输出 token 数、是否有推理内容、耗时；核对推理服务是否支持该参数（reasoning parser、chat template 中的思考开关等） | 两者无明显差别即未生效 | 修正参数映射或 chat template |
| 4 | 推理内容处理 | 检查多轮对话中上一轮推理内容是否被回填进历史；检查是否因 max_tokens 不足导致推理占满、答案为空或被截断 | 出现空答案、截断，或历史快速膨胀 | 调整 max_tokens；按模型要求处理历史中的推理内容 |
| 5 | 工具调用错误率 | 从日志统计 JSON 不合法、工具名错误、参数错误、选错工具、重复调用的次数 | 任一类超过 5% | 约束解码、减少可见工具、增加修复层 |
| 6 | 压缩时机与质量 | 记录压缩触发点；检查压缩后任务清单、已确认参数、文件路径等关键信息是否保留 | 压缩后丢任务或重复劳动 | 提前压缩；结构化状态不参与压缩 |
| 7 | 无关章节注入 | 检查审计会话的实际 prompt 中是否含 heartbeat、群聊、投递、cron 等章节 | 存在 | 按场景关闭 |
| 8 | 采样参数 | 检查 temperature、top_p 等设置 | 结构化输出使用较高 temperature 会增加格式错误 | 按调用角色分别设置（见 08 第 4.3 节） |
| 9 | 有效上下文 | 按 04 文档方法，在不同长度下测试召回和任务质量 | 找到质量明显下降的拐点 | 以拐点作为上下文预算上限 |

第 1~4、7、8 项多为配置问题，通常改参数即可；第 5、6、9 项需要结合运行时改造。

## 二、失败任务样本与标注

### 样本收集

- 首批 10~20 个真实审计任务，逐步扩充到 50 个以上。
- 覆盖类型：单步查询、单个审计程序、多步程序、底稿生成、一句话包含多项任务的请求。
- 每个样本保存：用户原始输入、完整请求与响应日志（含工具调用）、最终输出、审计人员对结果的评价。

### 标注模板

| 字段 | 说明 |
|---|---|
| 任务 ID | |
| 任务类型 | 查询 / 单程序 / 多步程序 / 底稿生成 / 多任务 |
| 是否完成 | 完成 / 部分完成 / 未完成 |
| 结果质量 | 正确 / 部分正确 / 错误 |
| 首个出错环节 | 需求理解 / 规划 / 工具选择 / 工具参数 / 工具结果理解 / 计算 / 遗漏子任务 / 上下文丢失 / 输出格式 / 超时 |
| 根因分类 | 配置 / 提示词 / 上下文 / 模型推理 / 工具缺失 / 数据问题 |
| 耗时、token 消耗 | |
| 备注 | 具体现象，附日志位置 |

### 根因到处理方式

| 根因 | 处理方式 | 参考文档 |
|---|---|---|
| 配置 | 修正参数 | 本文第一节 |
| 提示词 | 裁剪、按角色拆分提示词 | 01、08 |
| 上下文 | 预算与提前压缩 | 04 |
| 模型推理 | 规划-执行-验证、固定工作流 | 03、08 |
| 工具缺失 | 补充审计程序 | 05 |
| 数据问题 | 数据层标准化与前置检查 | 05、06 |

## 三、基准指标

| 指标 | 定义 |
|---|---|
| 任务完成率 | 完成的任务 / 全部任务 |
| 结果正确率 | 结果正确的任务 / 完成的任务 |
| 多任务漏项率 | 被遗漏的子任务 / 多任务请求中的全部子任务 |
| 工具调用错误率 | 出错的工具调用 / 全部工具调用 |
| 平均耗时、首字延迟 | |
| 人工修改量 | 底稿或结果被审计人员修改的比例 |
| 每任务 token 消耗 | |

每次改造（提示词、参数、工作流、模型）后，用同一批样本回归测试并对比指标，避免凭感觉判断优化效果。

## 四、阶段产出

1. **诊断报告**：每项检查结果、根因分布、配置类问题修复记录。
2. **评估集首版**：标注后的样本及标准答案。
3. **基准指标**：改造前的指标数值。
4. **改造优先级建议**：按根因分布确定 08 实施路线中各阶段的侧重点。
