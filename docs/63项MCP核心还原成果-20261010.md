## 3. 已核实的关键业务规则与旧行为

这些规则来自原生指令、常量或实际对照，不是根据函数名编造。

- 银行组合金额匹配从两条组合开始，按组合长度和原候选顺序搜索，差额必须 **小于 0.005**。名称包含关系直接得到相似度 1；其余使用词排序比率。L1–L9 全套匹配仍需继续改写。
- 账套总借贷平衡使用差额绝对值小于 0.01；父子科目期初/期末按“贷”方向取负后勾稽。`judge_calc` 返回首个异常科目，不是全部异常的拼接。
- 账龄冲减从旧账龄向新账龄分配；余额跨方向会重置。原 `_age_dict_reset` 是清零，不能误写成账龄整体顺延。贷方负余额存在前后字典别名行为，已作为兼容证据保留。
- PVM：价格效应 `(P1-P0)×V0`；数量效应 `(V1-V0)×(P0-U0)`；成本/交互项 `(P1-P0)×(V1-V0)−(U1-U0)×V1`。数量为零、主导因素及“综合变动”分支均有观察记录。
- 纸质核对按账簿顺序匹配未占用的提取记录，先原值精确匹配，再标准化匹配；一条提取记录只使用一次。提取结果中多个列表字段选择最长列表，不是逐行拼接所有列表。
- JET 同一字段的正向项取 OR，排除项再取 AND。原生规则与 Excel 模板有实质差异，例如“期末收入突击”的借/贷金额条件不同，模板还有重复规则名；[差异记录](../artifacts/core-logic-20261010/rule-source-differences.json)单独保留。
- 沪市 IPO 文件选择条件是 `fileType == 30` **或** `fileTypeMap == "I3010"`。深市选择 `matnm == "招股说明书"` 的披露材料，并加入问询回复附件。北市按 `SYG/SBG/BHG` 及问询回复集合取文件。
- 沪市旧映射中状态 `5` 为“注册结果”、`7` 为“中止及财报更新”、`9` 为“上市委审议”；北市 `P03` 为“通过”、`P04` 为“未通过”。未知编码保留原编码。不能按通用业务叫法替换这些已测规则。
- 关联方名称规范化的说明声称转小写，但实测保留大小写。D11 在已测分支中对参保人数 0、1 命中，2 不命中；D12 对“注销”“吊销”精确命中，“已注销”或“吊销，未注销”不命中。D09 已测分支检查股东/法定代表人变更涉及人员，未观察到根据审计日期设置时间窗口。
- 银行日期的紧凑八位数字分支直接拼接日期，`20240230` 会变成 `2024-02-30`，并不做日历有效性校验；合并列也存在把空值写成 `nan` 的行为。

这些是兼容基线，并不表示应把旧缺陷永久作为新应用的设计。后续改变规则时应明确记录预期差异，再做新结果验收。

## 5. 运行和独立迁移的实际边界

自有 Python 源码没有导入旧原生业务模块，也没有把原 EXE 的调用包装成“独立迁移”。运行这些核心仍需要普通开源依赖 `pandas`、`numpy`、`openpyxl`，本次验证的准确版本见 [requirements-research.txt](../src/audit-domain/recovered/requirements-research.txt)。依赖开源计算库与依赖原工具箱是两件事。

现有客户端打包 Python 没有完整包含这些依赖，本次也没有接入客户端调度。因此客户端中的旧桥接不会因本次代码提取自动消失；不能说目前的安装包已能在无旧工具箱的电脑上运行全部 63 项。

接下来的迁移应以逐项记录为依据：从共享核心补齐未验证分支 → 实现文件/模型/网络/Excel 适配 → 完整入口的正常与异常成果对照 → 接入自有调度 → 在没有旧 EXE 和 `.pyd` 的环境中打包验收。公开接口、认证、Excel/Word 应用或模型服务属于需单独接入的外部能力，不可能仅通过反编译消除。

## 6. 取证和复核方式

分析使用独立研究进程；原安装目录只读，网络被阻断或替换成合成响应。没有读取原配置、真实项目、财务数据库、Cookie 或用户输出。所有业务输入都是本项目内生成的合成样例。

从 PyInstaller 包取得 4,198 个冻结依赖代码文件，用于让研究进程识别公开依赖；这些不是 4,198 个审计功能。随后核对原生方法表、安全读取初始化常量、提取完整 `.text`、生成函数 C 伪代码并加入常量和原函数名注释。第三方库不计作自有业务算法。
