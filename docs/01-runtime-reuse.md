# 01 现有运行时的复用评估

现有模型运行时（基于 OpenClaw 机制还原的文档）是一个面向强模型、大上下文、多渠道（聊天、cron、heartbeat）的通用助理运行时。我们的瓶颈是模型推理深度不足、有效上下文有限，因此结论是：**保留控制流骨架，裁掉大部分提示词负担，补上缺失的结构化机制。**

> 注意：该文档本身声明是"基于文档结构的机制还原"，并非真实 prompt 字节。真正复用前应以 OpenClaw 源码和实际组装出的 prompt 为准。

## 可以直接沿用

| 组件 | 说明 |
|---|---|
| Agent loop | 调模型 → 执行 tool_call → 结果回填 → 循环，通用结构 |
| 工具 schema + 策略过滤 | 工具越少，弱模型越不容易选错 |
| exec 审批与权限模式 | 纯运行时逻辑，与模型强弱无关 |
| update_plan（单 in_progress） | 对弱模型尤其有用 |
| 子代理隔离 + 推式完成 | 思路正确，需改造为"子任务干净上下文" |
| Compaction 基本思路 | 需要更早、更激进地触发 |
| 审计/日志层 | 保留，用于调试自建 agent |

## 必须裁剪或修改

1. **System prompt 过重**：多轴引导、Tooling、Memory、Messaging、Heartbeat、Group Chat 等节加上单文件上限 20000 字符的引导文件，会大量占用有效上下文。按场景裁成最小集：角色、工具、执行偏置、当前计划。可从 `minimal` prompt mode 和 `lightContext` 起步。
2. **砍掉无关渠道逻辑**：cron、heartbeat、`NO_REPLY`、群聊静默、skill workshop 等个人助理场景能力。
3. **思考级别需自行实现**：`/think` 只是映射到各厂商原生推理参数，本地模型通常不支持。改用外部机制：先规划再执行、每步验证。
4. **Compaction 提前触发**：按固定比例（如有效上下文的 60%）主动压缩，工具输出在进入上下文前截断或摘要。
5. **记忆召回收紧**：限制召回条数和片段长度。

## 需要新增（原文档没有）

- **强制任务分解**：复杂请求先单独产出计划，再逐步执行，每步只带必要上下文。
- **代码强制验证**：执行后用工具确认结果，失败重试，而不是靠提示词要求"收尾前给证据"。
- **上下文预算管理**：代码统计 token，各部分设上限，超限自动裁剪。
- **输出格式容错**：tool_call JSON 修复、重试，或使用约束解码。
- **子任务干净上下文**：大任务拆给子会话，每个子会话只带自己需要的信息。
