## 2. 九类任务与实际能力的对应

本机 MCP 服务实际返回 63 个工具名，与注册元数据一致。加上 16 个内置入口，共 79 个注册入口。79 不是独立业务功能数，同一业务可能由多步骤或两种实现提供。

| 模块 | 阶段 | 显式工具引用（模块内去重） | 实际匹配入口（模块内去重） | 主要缺口 |
|---|---:|---:|---:|---|
| 表格与资料整理 | 4 | 12 | 18 | 同名重复、用途混淆；缺格式检查和表头/工作表选择 |
| 科目、账簿与凭证 | 5 | 10 | 12 | JET 引用误匹配重复检查；规则选择和字段确认不完整 |
| 月间分析与测算 | 6 | 7 | 7 | 缺本期/上期角色分配、科目选择与映射确认；多个不同分析共用表单 |
| 抽凭与抽样 | 4 | 2 | 2 | 实际只有截止测试抽样；入口名比现有能力范围更广，限制说明未展示 |
| 银行业务 | 5 | 5 | 5 | 文件路径仍需手填；数组参数全部变成字符串，未按账户/文件配置 |
| 底稿与明细表 | 7 | 6 | 6 | 缺工作/模板目录选择授权，配置 JSON 需手填；64 位 Excel 依赖未展示 |
| 披露、附注与链接 | 5 | 9 | 9 | 缺配置模板入口和变更预览；可选阶段把文件选择器一起隐藏 |
| 关联方与外部查询 | 4 | 7 | 7 | 整类隐藏文件选择，不能正常授权关联方所需数据目录；查询与资料处理混用 |
| 信息提取与辅助处理 | 3 | 9 | 9 | 直接文本/无参数查询与文件处理混在同一阶段，前端一律要求选文件 |

模块之间会复用工具，表中数量不能直接求和为总功能数。全局去重后，当前匹配可达 70 个入口，另有 9 个入口遗漏。“可达”仅指在界面上能找到，不代表参数正确或执行通过。

遗漏入口如下。内置简化功能不能自动视为原 MCP 的等价替代：

| mcp_multi_collect_folder | 多表汇集—文件夹配置方式 | 表格与资料整理 |

### 2.1 影响执行可信度的问题

1. **P0：7 个内置工具被错误派发给同名 MCP。** `select_column`、`fill_column`、`merge_column`、`add_column`、`dropsummary`、`text_match`、`voucher_check`。后端优先按裸名称查 MCP，即使已经找到内置工具也走 MCP 分支。本次隔离探针请求内置 `select_column`，确实调用了 MCP，参数却仍是内置的 `columns`。
2. **P0：MCP 返回业务错误仍记为成功。** 隔离探针模拟 `isError:true`，后台得到 `status:succeeded`。这是状态判定的真实代码行为；没有执行真实业务来制造错误。
3. **P1：同名不等于同功能。** 内置 `add_column` 是新增固定值列，MCP `add_column` 是合并相同名称列，真正的 MCP 插入固定列是 `insert_column`。前端模糊匹配也让 `jet_test` 带出 `duplicates`，不能以名称映射代替业务适配。
4. **P1：参数类型丢失。** 元数据映射只保留标签/必填/字符串默认值，全部用文本框收集并按字符串发送。银行流水多个数组、预览行数整数、覆盖确认布尔值等没有按 schema 构建。可选项空字符串也可能覆盖服务默认行为。
5. **P1：目录合同与授权冲突。** 工具要求 `work_dir`、`template_dir`、`data_dir`，前端目录却只能进入、不能选择授权。路径约束会拒绝这些目录。本次用合成项目与选中文件集合复现工作目录被拒绝。
6. **P1：任务生命周期不完整。** MCP 重试统一交给内置调度器；较长任务的前端等待窗口与 MCP 超时不一致；轮询结束但仍在运行时显示失败文案，缺持续恢复机制。
7. **P1：输入文件保护文案不可靠。** 部分 MCP 明确会覆盖原文件或重命名，例如选择列的非合并模式、月间 AI 分析的默认输出、图片重命名。必须按实际功能展示影响与副本策略，不能统一承诺不覆盖。

### 2.2 Skill 对应情况

项目内业务 skill 有 5 个：月间分析、明细表生成、JET、关联方识别、注协查询，分别应支撑月间分析、底稿、账簿、外部查询等任务。另外 3 个是查找/创建/校验 skill 的维护能力，不应计为 3 个审计业务页面。

`loadSkills` 在当前源码中没有运行调用；`skillContext` 仅被当前主程序未引入的兼容模块引用。当前九类任务没有实际加载这些 skill 来执行其要求。部分阶段名称与 skill 流程相似，但字段映射审阅、科目确认、配置校验等要求没有变成可验证的前置条件。

## 3. 每个功能是否明确文件格式

**没有。** 工作流定义有 `inputHint` 和依赖 `note`，界面未渲染；没有逐工具格式过滤与预检。测试中 `.txt` 可以在表格阶段选中。即使目录中包含 PDF，也不代表“查看数据结构”能读取 PDF；资料清单能处理任意文件只代表读取元信息。

| 能力 | 本次能确定的输入范围 | 仍需明确 |
|---|---|---|
| 内置表格读取与处理 | CSV、TSV、XLSX、XLSM | 工作表、表头行、编码、必需字段；其中 7 个入口还受错误派发影响 |
| 内置 PDF 文本提取 | PDF 文字层 | 扫描件不能当作已支持 OCR |
| 内置 Excel 链接提取 | XLSX、XLSM | 链接类型与结果呈现 |
| 文件资料清单 | 普通文件，读取名称/大小/哈希 | 不解析任意格式内容 |
| MCP 月间预览/结构识别 | 接口声明 Excel、CSV | Excel 具体扩展名、模板与字段约束 |
| MCP 企查查报告处理 | DOCX 所在文件夹 | 不应扩展宣称支持 DOC/PDF |
| MCP 纸质信息核对 | 接口声明 PDF/图片 | 图片后缀、大小、模型依赖 |
| MCP 明细表 | 数据源、Excel 模板目录、config/ 下 JSON 配置 | Excel 后缀、配置结构、模板检查；64 位 Excel 依赖 |
| MCP 函证/抽样/披露等配置类 | config_file 配置表 | 多数接口未列扩展名/版本；需要指定模板和引用资料校验 |
| 公告、IPO、注协等查询 | 代码/名称/日期/授权参数等 | 不应强制无关的文件上传 |

完整 79 项清单、每项归属及全部参数类型见 [功能与文件格式核对表](C:/Users/Install/Desktop/ai助手/docs/客户端功能与文件格式核对表-20261008.md)。MCP 未明确扩展名的项目已标“未列明”，没有擅自把“Excel”解释成支持所有表格格式。

每个正式功能至少应定义：输入角色、文件/目录/直接文本、后缀、份数、必需工作表/表头/字段、模板版本、编码/大小限制、输入是否被修改、输出格式与位置、错误恢复方式。文件选择后应立即反馈合规性；银行流水与序时账、本期与上期、数据源与模板必须分别指定。
