# 需求边界与验收

版本：v0.4；更新：2026-09-09。
主方案：[项目方案](项目方案.md)。本文件是计划，不表示应用、迁移或验收已经完成。

## 1. 首版范围原则

**首版完整迁移原工具箱全部实际业务功能，后续再做功能优化。** 取消原 A1–A4 首版、B1–B3 后续的范围划分。内部可以按模块开发和交付测试包，但正式首版不能缺失尚未完成的原有功能。

全部业务包括审计计算、财务分析、抽凭抽样、银行函证、PDF与附注、关联方、外部查询下载、文件与表格处理、模板、辅助工具以及原AI助手实际可用能力。不能用“不是核心审计功能”作为排除原工具的理由。

此前明确的界面及账号调整继续生效：删除旧功能列表/运行页，项目和设置重构，删除应用账号及项目数配额。保留这些页面原来承载的业务能力，不要求恢复旧页面或账号体系。

## 3. 全功能迁移验收

迁移依据为[原工具箱全功能迁移清单](原工具箱全功能迁移清单.md)，不能用文件数量代替功能数量。

每项实际业务功能必须完成：

1. 原入口与子功能、参数/默认值、依赖、输入/输出和模板的基线记录。
2. 新应用中可明确调用；有旧名称别名或可定位入口，不能只依赖自然语言猜测。
3. 正常样例、边界样例、错误样例的新旧行为对照；记录输入hash及运行环境。
4. 关键公式、金额/舍入、行列/排序、模板、格式、链接、原有宏行为和副作用的兼容验证。
5. 对适用的数据任务验证轻量/批量一致性；不可分割任务在批量调度下完整执行并说明粒度。
6. 外部服务、Office/OCR等依赖在所声明环境中实际验证，不用占位按钮、mock输出或“计划支持”充当迁移。
7. 阻塞、未知用途与差异全部闭环；归档结果和实现位置。

一项功能只有部分参数或一种输出格式通过，不计整项完成。未验证或依赖受阻是未完成状态，不能直接延期后宣称首版完整。范围例外必须明确记录用户决定，不能由实现方便程度自行产生。

工程支撑文件可以复用、替换或合并；有证据证明不是用户业务入口后记录归属，不必每个二进制文件都制作一个UI按钮。

## 4. 迁移与优化的界线

|首版必须做|首版之后做|
|---|---|
|原业务功能及参数、模板与行为兼容|新增审计规则和业务能力|
|此前确认的UI/项目/账号调整|重新设计原业务流程及默认操作口径|
|进程隔离、错误反馈、恢复、原件保护|改变阈值、抽样方法、匹配策略及结论标准|
|双模式所需的分批/落盘与等价算法实现|基于新算法重新定义结果含义|
|接口封装、模块拆分和可维护源码|业务模板重设计和新增分析解释功能|

不必照搬旧代码架构。首版允许内部实现改变，但用户可观察的业务语义必须有兼容依据。原行为疑似错误先登记和提示，不静默修正；导致崩溃、文件损坏等工程问题不能作为必须照搬的行为。

## 5. 双模式与输出验收

双模式设计继续保留，详见[数据处理双模式方案](数据处理双模式方案.md)。小任务不强制建分析库，大任务有资源预算、检查点和分卷能力，两种模式都默认本地执行。

已有功能不因暂时缺少SQL实现而消失：可在有界worker中按文件/工作簿排队执行，保留原义。涉及全局算子的任务不能拆错；单个任务超过预算时给出明确失败或支持的执行方式，不能静默截断。

额外证据索引、run manifest和诊断文件与原业务输出分开；不为增加元数据而破坏原模板和下游依赖。新路径由项目设置决定，原内容结构和业务命名规则按兼容基线验证。

## 6. 暂不新增的范围

远程worker、多用户云协作、超出原程序的任意第三方插件兼容与新业务算法，仍可留到后续。此条不能用于排除原程序已经提供的查询、MCP资源/提示、OCR或Office格式能力。

旧应用账号与配额按此前要求移除；第三方API凭据、服务费用、网络可用性等实际依赖需单独配置和记录，不复制旧账号或密钥。

## 7. 首版完成定义

全功能总账内首版业务项的实现和验证全部通过；未确认用途、未迁移选项、未核对模板和受阻依赖没有未解决缺项。安装包通过清洁环境、恢复、双模式和全工作流回归。

内部演示包可部分完成，但明确标记模块覆盖情况。空目录、占位入口、模拟数据或反编译产物本身都不代表完成迁移。性能宣称必须有实测记录。
