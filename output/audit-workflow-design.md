# AI 审计助手 · 审计工作流与阶段性成果设计

## 设计目标

一次审计任务被视为一个可恢复、可复核的 Task，而不是一段聊天记录。Task 固定保存：目标、输入快照、字段映射、规则版本、执行计划、阶段产物、异常证据和导出包。

每个阶段都回答四个问题：

1. 用户现在要做什么？
2. 系统正在做什么？
3. 用户必须确认什么？
4. 这一阶段留下什么可复核成果？

## 总体工作流

```text
目标与范围
    ↓
资料登记与质量检查
    ↓
字段映射与规则确认
    ↓
执行计划与资源评估
    ↓
执行与检查点
    ↓
异常、证据与人工复核
    ↓
结论与工作底稿导出
```

## 工作台结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 任务名称   当前阶段   输入快照   运行状态        本地运行 / 设置      │
├──────────────┬──────────────────────────────────────┬───────────────┤
│ 阶段导航     │ 当前阶段工作区                       │ 证据检查器    │
│              │                                      │               │
│ 01 目标      │ 阶段摘要                             │ 仅在选中证据、 │
│ 02 资料      │ 操作区                               │ 异常或字段时   │
│ 03 映射      │ 结果区                               │ 按需展开       │
│ 04 计划      │                                      │               │
│ 05 执行      │                                      │               │
│ 06 复核      │                                      │               │
│ 07 导出      │                                      │               │
└──────────────┴──────────────────────────────────────┴───────────────┘
```

左侧是阶段导航，不再放文件浏览。右侧是“证据检查器”，默认收起；只有点击异常、字段、文件或单元格时才打开，显示它为什么被纳入结果以及如何回到原始位置。

## 阶段一：目标与范围

### 用户流程

用户用自然语言描述目标，例如“检查本期银行流水中的异常大额交易”。系统识别审计模块、期间、对象和可能的规则，并生成一张可编辑的目标卡。

### 界面

- 目标描述编辑器：保留原话，可继续修改。
- 系统识别：模块、期间、对象、风险关键词。
- 建议程序：例如“大额交易筛选”“同日冲销检查”“异常对手方聚合”。
- 范围摘要：项目、期间、币种、是否包含期初/期末数据。
- `确认目标并添加资料` 是唯一主按钮。

### 阶段成果

**目标卡**：目标原文、结构化目标、适用规则候选、待确认问题、创建时间。

### 不能自动决定的内容

重大性水平、期间边界、是否包含未入账数据、异常规则阈值必须标为“需要确认”，不能被模型静默决定。

## 阶段二：资料登记与质量检查

### 系统流程

1. 扫描用户添加的文件夹或文件。
2. 计算输入快照和文件指纹。
3. 展开工作簿的工作表、列名、行数、空行和合并单元格。
4. 检测重复文件、格式不支持、读取失败、密码保护和期间不匹配。
5. 按“可直接使用 / 需要处理 / 无法使用”分组。

### 界面

- 文件表格默认展示状态和原因，不展示一排复选框。
- 用户通过 `纳入任务`、`排除`、`替换文件` 操作改变范围。
- 每个文件显示：文件名、类型、大小、时间范围、读取状态、指纹前缀。
- 顶部显示质量摘要：`12 个文件 · 10 个可用 · 1 个重复 · 1 个待处理`。

### 阶段成果

**证据登记表**：输入文件清单、文件指纹、解析状态、排除原因、项目授权范围。

**输入快照**：任务启动后不可静默改变；用户新增或替换资料时生成新快照并要求重新确认。

## 阶段三：字段映射与规则确认

### 系统流程

系统根据列名、样例值和数据类型推荐字段映射，并为每个映射给出置信度。规则卡说明输入字段、阈值、分组方式和输出字段。

### 界面

左侧是字段映射表，右侧是样例预览：

| 目标字段 | 来源列 | 置信度 | 状态 |
| --- | --- | ---: | --- |
| 交易日期 | 凭证日期 | 98% | 已确认 |
| 借方金额 | 借方金额 | 99% | 已确认 |
| 对手方 | 对方户名 | 82% | 需要确认 |
| 交易摘要 | 摘要 | 96% | 已确认 |

规则卡必须显示：规则名称、规则版本、参数、适用范围、预计输出。点击规则版本可查看变更说明。

### 阶段成果

**映射与规则快照**：字段来源、人工改动、规则版本、参数、假设和确认人/时间。

只有全部必需字段达到“已确认”或被明确标记为“不适用”，才能进入执行计划。

## 阶段四：执行计划与资源评估

### 系统流程

系统估算文件数、行数、内存、预计耗时和输出体量，默认推荐处理方式。轻量本地与大批量只作为计划详情，不再作为首页选框。

### 界面

- 计划摘要：`12 个文件 / 1,842,300 行 / 预计 4 分 20 秒`。
- 推荐方式：`自动 · 分 6 个批次执行`。
- 推荐原因：例如“预计内存高于轻量预算，将使用磁盘检查点”。
- 可展开“高级计划”：手动选择模式、并发数、缓存位置。
- 主按钮：`确认计划并开始执行`。

### 阶段成果

**执行计划**：输入快照、规则快照、计划模式、批次划分、资源预算和预计输出。

## 阶段五：执行与检查点

### 界面

阶段导航显示当前处于 `05 执行`，中心区使用任务时间线：

- 读取输入：已完成 12 / 12 文件。
- 标准化字段：已处理 1,200,000 / 1,842,300 行。
- 应用规则：第 4 / 6 批次。
- 写入中间结果：检查点已保存。
- 汇总异常：等待前序步骤完成。

每个步骤展开后显示输入引用、输出引用、耗时、警告数量和错误行清单。技术日志默认折叠。

### 状态

必须区分：排队、运行中、等待确认、已完成、已取消、失败、可恢复。取消只停止未提交步骤；恢复从最近检查点继续，不重复发布已经提交的结果。

### 阶段成果

**执行记录**：阶段状态、检查点、批次、文件/行计数、耗时、警告、错误、取消和恢复记录。

## 阶段六：异常、证据与人工复核

### 界面

结果进入“异常工作台”，默认按风险严重度和规则分组，不是一张无上下文的结果表。

顶部摘要：

- `发现 126 项`
- `高风险 8`
- `待复核 47`
- `已确认 71`

每个异常项显示：规则、风险解释、金额/数量、来源文件、工作表、行号或 PDF 页码、证据快照、相邻数据和处理状态。

状态操作：`确认异常`、`标记误报`、`需要补充资料`、`加入结论`。

点击来源打开右侧证据检查器，定位到原始文件的具体工作表、单元格、行或页码。证据检查器不修改原件，只允许添加审计备注。

### 阶段成果

**异常台账**：异常 ID、规则版本、证据定位、风险等级、复核状态、备注、处理人和时间。

**证据链**：从结论 → 异常 → 规则 → 字段 → 输入快照 → 原始文件的可追溯路径。

## 阶段七：结论与工作底稿导出

### 系统流程

系统根据已确认异常、未解决事项和执行记录生成结论草稿，同时列出仍需人工判断的项目。

### 界面

- 结论摘要：范围、程序、总体结果、重大异常、限制事项。
- 未解决事项：必须明确展示，不能藏在日志里。
- 输出包清单：异常明细表、汇总表、工作底稿、执行记录、证据索引。
- 每个输出显示版本、来源和生成时间。
- 主按钮：`生成导出包`；生成后改为 `打开导出目录`。

### 阶段成果

**结论快照**：结论文字、统计口径、异常台账版本和未解决事项。

**导出包**：输出文件、模板版本、公式/链接保留状态、证据索引和生成记录。

## 跨阶段交互

- 阶段导航显示四种状态：未开始、可进入、进行中、已完成；失败或待确认使用文字和图标同时表达，不能只靠颜色。
- 每次阶段确认都生成不可变快照；后续修改产生新版本并显示差异。
- 阶段切换使用“弹簧步骤条”表达当前阶段移动，但不延迟真实状态更新。
- 展开阶段详情使用真实内容高度过渡；键盘可操作，焦点不丢失。
- 长任务允许取消、重试、恢复；恢复前显示输入快照和已完成检查点。
- 所有阶段均提供“查看活动记录”，但技术日志默认折叠。
- reduced-motion 下保留状态变化、焦点和进度，不做位移动画。

## 首版验收标准

1. 用户不看帮助也能知道当前阶段和下一步动作。
2. 每个阶段完成后都有可命名、可回溯的产物。
3. 任意异常可以回到规则、字段和原始文件位置。
4. 处理中断后能明确知道哪些步骤已提交、哪些会重算。
5. 导出包能反向解释数据范围、规则版本和异常来源。
6. 轻量本地 / 大批量的技术选择不再打断主流程，只有在需要时进入高级计划。
